# Deploy RWiki 0.2.7 to production

## Background — why this isn't a simple image bump
0.2.7 introduced **multi-channelId** as a hard requirement:
- Backend **panics at startup** if no `[channels.<channelId>]` section is configured (`main.rs:321`).
- The widget now **requires** `channelId` in `init()` (`frontend/src/widget/config.ts:84`).
- `ChatRequest.channelId` became `Vec<String>` (commit `fa5239c`), so the existing `openapi.json` is stale.

The current production `config.toml` has no channels section and the docs-web widget passes no channelId → a straight image swap would leave RWiki refusing to start, and the docs widget broken even if it did. Three things must change.

## Code changes (local repo, 2 edits)

### 1. Fix docs-web widget to pass channelId
`docs-web/src/components/rwiki-chat-widget.tsx` — add `channelId: "help_center"` to the `RWikiChatOptions` type and the `init()` call. Without this the widget logs `[RWikiChat] channelId is required` and does not mount. This is the single required code fix; everything else is config/build/ops.

### 2. Regenerate openapi.json
```
cd backend && cargo run --manifest-path app/Cargo.toml -- --export-openapi ../docs-web/openapi.json
```
Reflects the `Vec<String>` channelId change from `fa5239c`. Verified: current file is v0.2.6 / single-value channelId.

## Server changes (ubuntu@152.32.249.178)

### 3. Update production config.toml — add channels section
Append to `/server/conf/rwiki/config.toml`:
```toml
[channels.help_center]
name = "Help Center"
[channels.help_center.suggested_questions]
default = ["How to get started", "What file formats are supported"]
zh-CN = ["如何快速上手", "系统支持哪些文件格式", "如何提升回答准确性"]
en = ["How to get started", "What file formats are supported"]
```
Preserves the existing `[chat]` global prompt (used as fallback via `resolved_system_prompt`). All existing keys (server/sqlite/llm/embedding/api/chat) left untouched. We read the live config — it's safe to edit in place before restarting.

### 4. Pull 0.2.7 and reset the SQLite database
As documented in `.ai/deployment.md` (WAL mode = 3 files):
```
docker pull ghcr.io/timzaak/rwiki:0.2.7
docker stop rwiki && docker rm rwiki
sudo rm -f /var/lib/docker/volumes/rwiki-data/_data/rwiki.db{,-wal,-shm}
sudo chown -R 1000:1000 /var/lib/docker/volumes/rwiki-data/_data
docker run -d --name rwiki --restart unless-stopped \
  -v rwiki-data:/app/data \
  -v /server/conf/rwiki/config.toml:/app/config.toml:ro \
  --network rmqtt-things-net \
  ghcr.io/timzaak/rwiki:0.2.7
docker logs rwiki --tail 8   # expect: "Database migrated..." + "Server listening on 0.0.0.0:8080"
```
Migration auto-runs on the empty DB (schema now includes the `channel_id` columns).

### 5. Seed data with channelId=help_center
Adapt `scripts/demo-start.py` upload logic to run against the server. English docs only (`docs-web/content/docs/*.mdx`, no `zh/`), plus the regenerated `openapi.json`. Each upload/publish call carries `channelId=help_center` (query param for publish, form field for upload). The `_inject_link_frontmatter` step is preserved so doc links resolve to `https://rwiki.fornetcode.com/docs/<slug>`. Without channelId the KB stays empty and RAG returns nothing. API token: `EFL-MxDrEfV-0pbk41Nsx1hsPGlVjkten3SfqmpVvZ0` (from live config).

## Local build + upload (docs-web)

### 6. Build docs-web and upload static site
```
cd docs-web && npm install && VITE_RWIKI_API_URL=https://rwiki.fornetcode.com npm run build
ssh ubuntu@152.32.249.178 "mkdir -p /server/www/rwiki"
scp -r .output/public/* ubuntu@152.32.249.178:/server/www/rwiki/
```

Built locally (server has no Node.js). `VITE_RWIKI_API_URL` must be the Caddy domain. The widget JS itself comes from the backend image (`/widget/rwiki-chat.js`), not the static site.
