## 故事 34：管理后台批量上下线文档 [US-CORE-034]

**优先级**: P0

**【用户故事】**
**作为**：Admin
**我希望**：在文档管理后台勾选多个文档，一次性提交"上线一批、下线一批"
**从而**：刷新 wiki 时能一次完成"下线老批次、上线新批次"，不必逐个操作，也不出现新老同时在线的重复召回或切换空窗

**【验收标准】**

**场景 1：批量切换生效**
```gherkin
Given 知识库中有一批已上线的老文档和一批待上线的新文档
When 运营在管理后台勾选新文档为上线、老文档为下线并提交
Then 新文档变为已发布、老文档变为草稿
And 提交后检索只命中新文档内容、不命中老文档内容
And 切换过程中提问始终能得到回答，无空窗、无同一内容重复召回
```

**场景 2：未改动内容不丢失**
```gherkin
Given 新批次中部分内容与线上老批次完全相同
When 运营上线新批次并下线老批次
Then 这些相同内容在新批次下仍可被检索和引用，不丢失
```

**场景 3：混入未就绪文档**
```gherkin
Given 勾选上线的文档中包含仍在处理中或处理失败的文档
When 运营提交批量操作
Then 系统逐条返回每项是否生效及原因，未就绪项不生效
And 已满足条件的项正常生效，不被整体回滚
```

## 故事 35：用 API Key 登录文档管理后台 [US-CORE-035]

**优先级**: P1

**【用户故事】**
**作为**：Admin
**我希望**：用系统已有的 API Key 在浏览器登录文档管理后台
**从而**：能在可视化界面管理文档，而不必直接调用 API

**【验收标准】**

**场景 1：正确 Key 登录**
```gherkin
Given 运营持有有效的 API Key
When 在登录页输入该 Key 并提交
Then 校验通过，进入文档管理后台
And 后续管理操作自动携带该 Key
```

**场景 2：错误 Key 被拒**
```gherkin
Given 运营输入了错误或失效的 API Key
When 提交登录
Then 提示 Key 无效，不进入管理后台
```

**场景 3：Key 失效后重新登录**
```gherkin
Given 运营已登录，但后续请求携带的 Key 失效
When 访问管理后台
Then 被引导回登录页重新输入 Key
```

## 故事 36：对指定文档集合运行评测 [US-CORE-036]

**优先级**: P1

**【用户故事】**
**作为**：Admin
**我希望**：对指定的一组文档运行 RAG 评测
**从而**：能在上线前预演评测尚未发布的新批次，或在特定文档范围内评估检索质量

**【验收标准】**

**场景 1：上线前预演评测草稿批次**
```gherkin
Given 知识库中有一批尚未上线（草稿）的新文档
When 评测者指定这批文档运行评测
Then 评测检索结果只来自这批文档，不受"仅已发布可见"限制
And 评测返回检索命中、上下文与生成答案供评估
```

**场景 2：不指定集合时维持线上行为**
```gherkin
Given 评测者未指定文档集合
When 运行评测
Then 评测检索与线上对话一致，只命中已发布文档
```
