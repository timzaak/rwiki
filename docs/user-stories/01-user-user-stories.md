## 故事 1：上传 xlsx 文件到知识库 [US-CORE-001]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：通过 API 上传 xlsx 文件到知识库，系统自动解析并索引其中的内容
**从而**：我可以针对文件中的数据进行提问

**【验收标准】**

**场景 1：上传 xlsx 并解析成功**
```gherkin
Given 知识库当前为空
When 调用上传 API 上传一个有效的 xlsx 文件（包含 Title 和 Markdown Content 列）
Then API 返回上传成功，包含文档 ID、文件名、行数，文档状态为"草稿"
And 调用文档列表 API 可查看到该文档
```

**场景 2：上传不支持的文件格式**
```gherkin
Given 用户准备上传文件
When 调用上传 API 上传一个 .pdf 或 .csv 文件
Then API 返回 400 错误，提示"仅支持 xlsx 格式文件"
```

**场景 3：上传空文件或无数据的工作表**
```gherkin
Given 用户准备上传一个 xlsx 文件
When 调用上传 API 上传该文件，但文件没有有效数据行（仅表头或完全为空）
Then API 返回错误提示（如"文件中没有可用的数据"），不创建文档记录
```

## 故事 2：与知识库进行多轮对话 [US-CORE-002]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：以多轮对话的方式向知识库提问，系统基于已索引的文档内容回答
**从而**：我可以用自然语言查询 xlsx 中的数据，并通过追问获取更详细的信息

**【验收标准】**

**场景 1：基于文档内容回答问题**
```gherkin
Given 用户已通过 US-CORE-001 上传并发布了至少一个 xlsx 文档
When 用户输入一个与文档内容相关的问题
Then 系统以流式方式返回基于文档内容的回答
And 回答中引用的数据可在原文档中找到依据
```

**场景 2：多轮上下文追问**
```gherkin
Given 用户刚问过"销售额最高的月份是哪个"，系统回答"3月"
When 用户追问"那个月的具体数据呢"
Then 系统理解"那个月"指代"3月"，返回 3 月的详细数据
```

**场景 3：提问超出知识库范围**
```gherkin
Given 知识库中没有与用户问题相关的数据
When 用户提出一个完全无关的问题（如"今天的天气"）
Then 系统回复"当前知识库中没有找到相关信息"，不编造答案
```

## 故事 7：上传结构化 Wiki xlsx 文件 [US-CORE-007]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：通过 API 上传包含 Title、Markdown Content 等列的 xlsx 文件，系统按列名解析为结构化 Wiki 页面并索引
**从而**：我可以针对每个 Wiki 页面的内容进行精确检索，并获得带来源引用的回答

**【验收标准】**

**场景 1：上传结构化 xlsx 并成功解析**
```gherkin
Given 用户准备了一个 xlsx 文件，首行为表头，包含 Title 和 Markdown Content 列（可选 Locale、Link、Tags 列）
When 调用上传 API 上传该文件
Then API 返回成功，系统解析每行为一个 Wiki 页面，按 Markdown 标题结构分块
And 每个分块携带 title、locale、link、tags、section 元数据
And 文档状态为"草稿"
```

**场景 2：缺少必填列**
```gherkin
Given 用户准备上传一个 xlsx 文件，表头缺少 Title 或 Markdown Content 列
When 调用上传 API 上传该文件
Then API 返回错误，提示"缺少必填列"，文件不被导入
```

**场景 3：行数据缺失必填字段**
```gherkin
Given 用户准备上传一个 xlsx 文件，某些行的 Title 或 Markdown Content 为空
When 调用上传 API 上传该文件
Then API 返回错误，拒绝整个文件的导入，提示哪些行缺失必填字段
```

**场景 4：Markdown 内容无标题结构**
```gherkin
Given 用户上传的 xlsx 中某行的 Markdown 内容没有标题（无 # 标记）
When 系统解析该行
Then 该 Markdown 内容作为整体生成分块，section 元数据为空
And 分块仍可被正常检索
```

**作为**：User
**我希望**：通过修改配置文件自定义知识库助手的角色描述和回答规则
**从而**：我可以根据不同使用场景（如技术文档助手、客服助手、产品助手）调整助手的行为风格和专业领域

**【验收标准】**

**场景 1：配置自定义提示词后生效**
```gherkin
Given 管理员在 config.toml 的 [chat] 段配置了自定义系统提示词
When 服务重启后用户发起对话
Then 助手使用新配置的角色描述和回答规则进行回答
And RAG 检索上下文仍然正常注入和引用
```

**场景 2：未配置时使用默认值**
```gherkin
Given config.toml 中未配置 [chat] 段或 system_prompt 字段为空
When 用户发起对话
Then 助手使用默认提示词（与当前硬编码行为一致）
And 回答质量与配置前无差异
```

**场景 3：自定义提示词不影响上下文检索**
```gherkin
Given 管理员配置了自定义角色描述（如"你是一个客服助手"）
When 用户提问
Then 系统仍然基于知识库文档检索相关内容
And 回答中仍然包含来源引用
And 仅角色语气和回答风格按自定义提示词调整
```

**【用户故事】**
**作为**：User
**我希望**：追问时系统自动理解我的指代和省略，不需要我重复完整问题

**场景 1：指代消解后检索到正确内容**

**场景 2：省略补充后检索到正确内容**
```gherkin

When 用户追问"那4月呢"
```

```gherkin

And 用户端不感知错误，回答正常返回
```

```gherkin
Then 系统基于当前生效规范生成结构化调用计划
And 计划包含标题、每步操作说明、请求参数、风险等级和认证需求
And 计划状态为"待审批"，未审批前不执行任何调用
```

**场景 2：无可用规范时尝试编排**
```gherkin
Given 系统中没有生效的 OpenAPI 规范
When 用户在 API 编排模式下输入操作需求
Then 系统提示"暂无可用的 API 规范，请联系管理员上传"
And 不生成调用计划
```

**场景 3：意图无法匹配到现有接口**
```gherkin
Given 管理员已激活 OpenAPI 规范
When 用户描述的操作无法由当前规范中的接口完成
Then 系统提示无法匹配，并说明当前可用的操作范围
And 建议用户调整描述或联系管理员补充规范
```

## 故事 16：审批并执行 API 调用计划 [US-CORE-016]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：在审批调用计划后，系统安全执行并展示每步的请求和结果
**从而**：我可以在确认安全后让系统自动完成多步 API 调用，并实时了解执行进度

**【验收标准】**

**场景 1：审批并执行读操作计划**
```gherkin
Given 系统已生成一个调用计划，所有步骤均为读操作
When 用户确认执行
Then 前端按步骤顺序执行每个 API 调用
And 逐步展示每步的请求内容、响应结果、状态和耗时
And 所有步骤完成后显示"执行完成"状态
```

**场景 2：审批写操作计划需要额外确认**
```gherkin
Given 系统已生成一个包含写操作（如创建、更新）的调用计划
When 用户首次确认执行
Then 系统提示该计划包含数据修改操作，要求二次确认
And 用户二次确认后才开始执行
```

**场景 3：目标 API 需要认证时由用户提供**
```gherkin
Given 调用计划中标注了目标 API 需要认证（如 Bearer Token）
When 用户准备审批执行
Then 系统展示需要填写的认证字段，用户输入后才开始执行
And 用户输入的认证信息仅保存在浏览器内存中，不持久化
```

**场景 4：执行中某步骤失败**
```gherkin
Given 调用计划正在执行中
When 某一步骤执行失败（如接口返回错误）
Then 后续步骤不再执行
And 已成功步骤的结果保留展示
And 失败步骤显示错误信息和原因
And 整体状态显示为"执行失败"
```

**场景 5：执行中规范被替换**
```gherkin
Given 调用计划正在执行中
When 管理员上传了新的 OpenAPI 规范
Then 下一步执行前系统检测到规范版本不匹配
And 系统中止执行并提示用户"API 规范已更新，请重新生成调用计划"
And 已执行的步骤结果保留展示
```

**场景 6：执行结果中敏感字段脱敏**
```gherkin
Given 调用计划执行完成
When 某步骤的响应中包含 token、password 或 secret 等字段
Then 展示时这些字段的值被脱敏处理（如显示为 ***）
```

## 故事 18：上传 OpenAPI JSON 文件到知识库 [US-CORE-018]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：通过 API 上传 OpenAPI 3.x JSON 文件到知识库，系统自动解析每个 API 端点为独立知识页并索引
**从而**：我可以针对 API 文档内容进行提问，获得基于文档的回答

**【验收标准】**

**场景 1：上传合法 OpenAPI JSON 并成功解析**
```gherkin
Given 知识库当前为空
And 用户准备了一个 OpenAPI 3.x JSON 文件，包含多个端点
When 调用上传 API 上传该 .json 文件
Then API 返回上传成功，文档状态为"草稿"
And 每个 API 端点（path + method 组合）生成一个独立的知识页
And 知识页内容包含端点的路径、方法、描述、参数和响应信息
```

**场景 2：上传非 OpenAPI 格式的 JSON**
```gherkin
Given 用户准备了一个普通 JSON 文件（不包含 openapi 字段）
When 调用上传 API 上传该 .json 文件
Then API 返回 400 错误，提示"不是有效的 OpenAPI 3.x 格式"
```

**场景 3：上传 paths 为空的 OpenAPI JSON**
```gherkin
Given 用户准备了一个 OpenAPI JSON 文件，结构合法但 paths 为空
When 调用上传 API 上传该文件
Then API 返回 400 错误，提示文件中没有可解析的 API 端点
```

**场景 4：上传后通过聊天查询 API 文档**
```gherkin
Given 用户已上传并发布了一份 OpenAPI JSON 文档
When 用户在聊天中提问"有哪些接口可以创建用户"
Then 系统基于文档内容返回相关端点信息
And 回答中包含来源引用，显示端点路径和摘要
```

**场景 5：上传包含 $ref 引用的 OpenAPI JSON**
```gherkin
Given 用户准备了一个 OpenAPI JSON 文件，端点描述中引用了 components/schemas 中的定义
When 调用上传 API 上传该文件
Then 系统解析时将引用的 schema 摘要内联到端点描述中
And 每个端点的知识页内容自包含，无需额外引用其他 schema 定义
```

## 故事 17：在知识库问答与 API 编排之间切换 [US-CORE-017]

**优先级**: P1

**【用户故事】**
**作为**：User
**我希望**：在聊天中切换知识库问答和 API 编排两种模式
**从而**：我可以在同一聊天入口既查询知识库又编排 API 调用，两种能力互不干扰

**【验收标准】**

**场景 1：切换到 API 编排模式**
```gherkin
Given 用户当前处于知识库问答模式
When 用户选择切换到 API 编排模式
Then 聊天输入区域更新为 API 编排模式
And 后续输入将生成 API 调用计划而非知识库问答
```

**场景 2：问答模式中自动建议切换**
```gherkin
Given 用户当前处于知识库问答模式
And 系统中已有生效的 OpenAPI 规范
When 用户输入明显是 API 操作意图（如"帮我查询待处理用户并发通知"）
Then 系统提示"这看起来是 API 调用任务，是否生成调用计划？"
And 用户确认后才进入 API 编排流程
And 用户拒绝则继续按知识库问答处理
```

**场景 3：执行完成后追问结果**
```gherkin
Given 用户刚完成一次 API 调用计划执行
When 用户追问"解释一下这次结果"或"总结失败原因"
Then 系统基于执行日志生成自然语言解释
And 不把执行结果写入知识库向量索引
```
