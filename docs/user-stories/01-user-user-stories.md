## 故事 1：上传 xlsx 文件到知识库 [US-CORE-001]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：通过 API 上传 xlsx 文件到知识库，系统自动解析并索引其中的内容
**从而**：我可以针对文件中的数据进行提问

**【验收标准】**

**场景 1：上传 xlsx 并解析成功**
```gherkin
Given 知识库当前为空
When 调用上传 API 上传一个有效的 xlsx 文件（包含 Title 和 Markdown Content 列）
Then API 返回上传成功，包含文档 ID、文件名、行数，文档状态为"草稿"
And 调用文档列表 API 可查看到该文档
```

**场景 2：上传不支持的文件格式**
```gherkin
Given 用户准备上传文件
When 调用上传 API 上传一个 .pdf 或 .csv 文件
Then API 返回 400 错误，提示"不支持的文件格式，支持 xlsx/md/mdx/json"
```

**场景 3：上传空文件或无数据的工作表**
```gherkin
Given 用户准备上传一个 xlsx 文件
When 调用上传 API 上传该文件，但文件没有有效数据行（仅表头或完全为空）
Then API 返回错误提示（如"文件中没有可用的数据"），不创建文档记录
```

## 故事 2：与知识库进行多轮对话 [US-CORE-002]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：以多轮对话的方式向知识库提问，系统基于已索引的文档内容回答
**从而**：我可以用自然语言查询 xlsx 中的数据，并通过追问获取更详细的信息

**【验收标准】**

**场景 1：基于文档内容回答问题**
```gherkin
Given 用户已通过 US-CORE-001 上传并发布了至少一个 xlsx 文档
When 用户输入一个与文档内容相关的问题
Then 系统以流式方式返回基于文档内容的回答
And 回答中引用的数据可在原文档中找到依据
```

**场景 2：多轮上下文追问**
```gherkin
Given 用户刚问过"销售额最高的月份是哪个"，系统回答"3月"
When 用户追问"那个月的具体数据呢"
Then 系统理解"那个月"指代"3月"，返回 3 月的详细数据
```

**场景 3：提问超出知识库范围**
```gherkin
Given 知识库中没有与用户问题相关的数据
When 用户提出一个完全无关的问题（如"今天的天气"）
Then 系统回复"当前知识库中没有找到相关信息"，不编造答案
```

## 故事 7：上传结构化 Wiki xlsx 文件 [US-CORE-007]

**优先级**: P0

**【用户故事】**
**作为**：User
**我希望**：通过 API 上传包含 Title、Markdown Content 等列的 xlsx 文件，系统按列名解析为结构化 Wiki 页面并索引
**从而**：我可以针对每个 Wiki 页面的内容进行精确检索，并获得带来源引用的回答

**【验收标准】**

**场景 1：上传结构化 xlsx 并成功解析**
```gherkin
Given 用户准备了一个 xlsx 文件，首行为表头，包含 Title 和 Markdown Content 列（可选 Locale、Link、Tags 列）
When 调用上传 API 上传该文件
Then API 返回成功，系统解析每行为一个 Wiki 页面，按 Markdown 标题结构分块
And 每个分块携带 title、locale、link、tags、section 元数据
And 文档状态为"草稿"
```

**场景 2：缺少必填列**
```gherkin
Given 用户准备上传一个 xlsx 文件，表头缺少 Title 或 Markdown Content 列
When 调用上传 API 上传该文件
Then API 返回错误，提示"缺少必填列"，文件不被导入
```

**场景 3：行数据缺失必填字段**
```gherkin
Given 用户准备上传一个 xlsx 文件，某些行的 Title 或 Markdown Content 为空
When 调用上传 API 上传该文件
Then API 返回错误，拒绝整个文件的导入，提示哪些行缺失必填字段
```

**场景 4：Markdown 内容无标题结构**
```gherkin
Given 用户上传的 xlsx 中某行的 Markdown 内容没有标题（无 # 标记）
When 系统解析该行
Then 该 Markdown 内容作为整体生成分块，section 元数据为空
And 分块仍可被正常检索
```

**作为**：User

**从而**：我可以根据不同使用场景（如技术文档助手、客服助手、产品助手）调整助手的行为风格和专业领域

**【验收标准】**

**场景 1：配置自定义提示词后生效**
```gherkin
Given 管理员在 config.toml 的 [chat] 段配置了自定义系统提示词
When 服务重启后用户发起对话
Then 助手使用新配置的角色描述和回答规则进行回答
And RAG 检索上下文仍然正常注入和引用
```

**场景 2：未配置时使用默认值**
```gherkin
Given config.toml 中未配置 [chat] 段或 system_prompt 字段为空
When 用户发起对话
Then 助手使用默认提示词（与当前硬编码行为一致）
And 回答质量与配置前无差异
```

**场景 3：自定义提示词不影响上下文检索**
```gherkin
Given 管理员配置了自定义角色描述（如"你是一个客服助手"）

Then 系统仍然基于知识库文档检索相关内容
And 回答中仍然包含来源引用
And 仅角色语气和回答风格按自定义提示词调整
```

**【用户故事】**
