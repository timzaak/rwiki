## 2. 范围界定

### 2.1 包含功能

- **OpenAPI 规范管理**：管理员上传 OpenAPI 3.1.0 JSON，系统进行结构校验和 AI 注释充分性评估，通过后成为唯一生效规范
- **调用计划生成**：基于生效规范和用户自然语言意图，AI 生成结构化调用计划
- **审批与执行**：用户审批调用计划后，前端受控执行器按步骤顺序执行 API 调用
- **执行结果展示**：逐步展示每个 API 调用的请求、响应、状态和耗时
- **模式切换**：用户可在知识库问答和 API 编排之间显式切换，系统可辅助建议切换
- **安全约束**：认证凭据隔离、敏感字段脱敏、写操作二次确认、执行范围受限于生效规范

### 2.2 不包含功能 (Out of Scope)

- OpenAPI YAML 格式支持
- 多规范版本并存或用户选择版本
- OAuth2、多步登录、Cookie 会话等复杂认证方式
- 数组迭代、嵌套表达式或通用模板语言
- 执行策略（skip_and_continue、retry_once）或自动回滚
- CORS 处理（目标 API 与本系统同域部署）
- 文件上传、流式响应、WebSocket 类型接口
- 跨规范调用或任意 JavaScript 执行
- Web Worker 执行线程隔离（首期在主线程执行）
- 执行结果持久化或写入知识库向量索引
- PATCH / DELETE 方法（首期仅 GET / POST）

### 2.3 依赖项

- **API Token 鉴权**：管理员接口依赖 `docs/prd/infrastructure/api-token-auth.md`
- **现有聊天基础设施**：SSE 流式推送、rig Agent 框架、对话状态管理
- **LLM Provider**：调用计划生成和注释评估依赖 `docs/prd/infrastructure/model-providers.md`
- **同域部署**：目标 API 与本系统部署在同一域名下

## 3. 需求概述

### 3.1 功能描述

在现有 RAG 知识库问答能力基础上，新增 API 调用编排能力。管理员通过上传 OpenAPI JSON 定义系统可调用的 API 规范；普通用户在聊天中用自然语言描述 API 操作意图，系统基于生效规范生成结构化调用计划，用户审批后由前端受控执行器安全执行。

这为用户提供了一种"说出你想做什么，审批后自动完成"的 API 使用方式，无需手动拼接请求、理解接口细节或编写脚本。

### 3.2 关键特性

- **规范驱动的受控编排**：所有可调用 API 严格来自管理员上传并校验通过的 OpenAPI 规范，AI 不能调用规范之外的接口
- **计划-执行分离**：AI 生成可审阅的结构化调用计划，用户审批后才执行，写操作需要二次确认
- **认证隔离**：目标 API 认证凭据仅存在于前端内存，不进入 LLM、后端日志或持久化存储
- **与 RAG 问答共存**：API 编排和知识库问答作为两种独立模式，上下文隔离、互不干扰

## 4. 业务规则与状态

### 4.1 业务规则

**规范管理规则**：
- 系统只允许一个生效（active）的 OpenAPI 规范
- 新规范校验通过后原子替换旧版本；校验失败时保留旧版本
- 校验包含两层：结构合法性检查和 AI 注释充分性评估，两层都通过才允许生效
- 校验失败时返回可定位的问题列表，管理员修正后重新上传

**调用计划规则**：
- 调用计划中的每个操作必须对应生效规范中已定义的 operationId
- 计划包含风险等级标识（read/write），写操作必须标记 `requiresApproval = true`
- 计划中声明的认证需求只能来自 OpenAPI securitySchemes，AI 不能自造认证方式
- 计划最多 5 个步骤，总执行超时 30 秒

**执行规则**：
- 前端执行器按步骤顺序执行，任一步骤失败立即中止后续步骤（abort_on_error）
- 执行前用户必须审批计划；写操作需要二次确认
- 目标 API 需要认证时，用户在审批界面提供凭据，凭据仅保存在浏览器内存中
- 响应展示前对 token、password、secret 等常见敏感字段脱敏
- 同一时间只允许一个计划执行

**上下文隔离规则**：
- 生成 API 调用计划时不注入 RAG 检索结果，只使用生效规范摘要和用户意图
- API 执行结果不写入知识库向量索引，只作为当前会话临时消息
- 目标 API 认证字段不进入 LLM prompt、后端日志或任何持久化存储
- RAG 文档和 OpenAPI 规范对同一接口描述冲突时，执行以 OpenAPI 规范为准

**规范替换与执行一致性**：
- 执行过程中管理员替换了生效规范，执行器在下一步执行前检测版本不匹配并中止执行

### 4.2 关键状态与异常

**OpenAPI 规范状态**：

| 状态 | 含义 |
|------|------|
| 校验中 | 刚上传，正在进行结构和注释评估 |
| 已生效 | 校验通过，作为当前唯一 active 规范 |
| 已拒绝 | 校验失败，未替换旧版本 |

**调用计划状态**：

| 状态 | 含义 |
|------|------|
| 生成中 | AI 正在基于用户意图生成计划 |
| 待审批 | 计划已生成，等待用户审批 |
| 执行中 | 用户已审批，前端执行器正在逐步执行 |
| 已完成 | 所有步骤执行成功 |
| 已失败 | 某步骤失败，后续步骤已中止 |
| 已中止 | 规范版本不匹配或用户取消，执行已停止 |

**关键异常场景**：

- **无生效规范**：用户尝试 API 编排时提示"暂无可用 API 规范"
- **意图无法匹配**：用户描述的操作无法映射到规范中的接口，提示调整描述
- **步骤执行失败**：失败步骤显示错误信息，后续步骤不执行，已成功步骤保留展示
- **执行中超时**：总执行时间超过 30 秒，中止执行并标记为已失败
- **规范中途替换**：执行器检测到版本不匹配，中止执行并提示重新生成计划
- **浏览器刷新或关闭**：未完成的执行不保留，用户需重新审批执行（认证字段只存在于内存）

## 5. 功能需求

### 5.1 核心需求

1. **OpenAPI 规范上传与校验**
   - 管理员上传 OpenAPI 3.1.0 JSON 文件
   - 系统进行结构合法性检查（JSON 格式、OpenAPI 版本、必填字段、operationId 唯一性等）
   - 结构校验通过后进行 AI 注释充分性评估（接口用途、参数说明、响应结构、编排可用性）
   - 两层校验都通过后成为唯一生效规范；任一层失败则拒绝并返回问题列表

2. **调用计划生成**
   - 用户在 API 编排模式下用自然语言描述操作意图
   - 系统基于生效规范摘要生成结构化调用计划
   - 计划包含标题、步骤列表、每步操作说明和参数、风险等级、认证需求
   - 大型规范（超过 50 个 operation）时提示管理员精简

3. **计划审批与前端执行**
   - 用户审批调用计划后才可执行
   - 写操作需要二次确认
   - 目标 API 需要认证时，用户在审批界面提供凭据
   - 前端受控执行器按步骤顺序构造并执行请求
   - 支持前一步响应字段通过简单点路径引用传递给下一步

4. **执行结果展示**
   - 逐步展示每个 API 调用的请求内容、响应结果、状态和耗时
   - 失败步骤显示错误信息和原因
   - 敏感字段值脱敏展示

5. **模式切换**
   - 用户可在知识库问答和 API 编排模式间显式切换
   - 知识库问答模式下，系统检测到 API 操作意图时可建议切换（用户确认后才切换）

### 5.2 验收目标

- 管理员上传一份包含至少 5 个接口的 OpenAPI 3.1.0 JSON，系统完成两层校验后生效，返回校验摘要
- 管理员上传缺少必填字段或注释不充分的 JSON，系统拒绝并返回可操作的问题列表
- 用户输入"查询待处理用户"类意图，系统基于生效规范生成包含步骤、参数和风险标识的结构化调用计划
- 用户审批后，前端执行器按计划顺序执行，逐步展示请求/响应/状态/耗时
- 写操作计划需要二次确认才能执行
- 目标 API 需要认证时，用户提供的凭据不出现在 LLM prompt、后端日志或持久化存储中
- 执行失败时已成功步骤结果保留，失败步骤显示错误原因
- RAG 问答和 API 编排两种模式独立工作，上下文互不干扰

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：管理员接口（上传/查看/清空规范）需要 API Token 鉴权；调用计划生成接口鉴权方式与现有 `/api/chat` 保持一致
- **访问控制**：管理员操作（规范管理）需要管理员权限；普通用户操作（计划生成、执行）不需要额外权限
- **接口能力边界**：
  - 管理员：上传规范（含校验）、查看 active 规范元数据、下载规范原文、清空规范
  - 用户：生成调用计划（SSE 流式推送）、计划生成后后端二次校验 plan 结构
- **执行路径**：前端执行器直接调用目标 API，不经过本系统后端代理
- **兼容性**：不修改现有 `/api/chat` 接口行为

## 7. 前端/交互约束

**适用性**: 适用

### 7.1 页面入口

- 聊天输入区域提供模式切换入口（"问知识库" / "调用 API"）
- 管理后台提供 OpenAPI 规范管理面板（上传、查看、清空）

### 7.2 关键交互

- **模式切换**：用户在聊天输入旁切换模式；切换后输入区域和行为模式随之变化
- **调用计划展示**：计划以结构化卡片形式展示，包含标题、步骤列表、风险标识、认证需求
- **审批操作**：用户点击"执行"按钮审批计划；写操作弹出二次确认对话框
- **认证字段填写**：目标 API 需要认证时，审批界面显示对应输入框
- **执行进度**：逐步展示每步执行状态（待执行/执行中/成功/失败），含请求、响应、耗时
- **错误展示**：失败步骤突出显示错误信息和原因
- **规范管理**：管理员上传文件后显示校验进度和结果（成功/问题列表）

### 7.3 状态反馈

- 规范上传中：显示校验进度
- 规范校验失败：显示问题列表，每个问题包含位置和说明
- 计划生成中：打字动画指示
- 计划待审批：计划卡片显示"待审批"状态和"执行"按钮
- 执行中：每步实时更新状态和结果
- 执行完成：显示"执行完成"汇总
- 执行失败：失败步骤高亮，显示错误原因
- 无可用规范：提示用户联系管理员

## 8. 已确认决策

- **单一生效规范**：系统只保留一个 active OpenAPI 规范，新版本校验通过后原子替换
- **两层校验**：结构合法性 + AI 注释充分性评估，两层都通过才允许生效
- **结构化调用计划**：AI 输出结构化 plan 而非任意 JS，前端受控执行器解释执行
- **前端执行**：执行器在浏览器端运行，不经过本系统后端代理
- **认证隔离**：目标 API 认证凭据仅存于前端内存，不进入 LLM/日志/持久化
- **MVP 方法限制**：首期仅支持 GET 和 POST
- **模板表达式限制**：仅支持 `{{step_N.response.field}}` 简单点路径，不支持数组迭代
- **执行策略**：首期仅 abort_on_error，不支持 retry 或 skip
- **无 CORS 处理**：目标 API 与本系统同域部署
- **无自动回滚**：API 调用副作用不可通用回滚，执行结果完整展示供用户手动处理
- **模式显式切换**：用户主动选择 API 编排模式，自动路由仅作为辅助建议
- **Plan 生成鉴权**：与现有 `/api/chat` 保持一致，不引入新认证机制
