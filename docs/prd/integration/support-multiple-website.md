## 2. 范围界定

### 2.1 包含功能

- 通过配置文件静态定义一个或多个频道，每个频道拥有全局唯一的 `channelId`。
- 文档、分块、发布状态、聊天会话、反馈、低相关召回记录、推荐问题、系统提示词均按 `channelId` 隔离。
- Widget 通过初始化配置声明目标频道；主站前端通过 URL path 后缀声明目标频道。
- 请求未携带 `channelId` 或携带未配置的 `channelId` 时，系统拒绝服务并给出明确提示。
- 全局 CORS 配置控制哪些第三方域名可以嵌入 Widget；所有频道共享同一份 CORS 策略。
- 每个频道可独立配置系统提示词、推荐问题等影响聊天行为的参数。
- 管理后台展示已配置的频道列表，运营操作按当前选定频道限定范围。

### 2.2 不包含功能 (Out of Scope)

- 运行时动态创建/删除频道（频道定义仅通过修改配置文件后加载）。
- 数据迁移方案：升级前已存在的无 `channelId` 历史数据由运营方人工规划回填，系统不在运行时自动归属。
- 按频道隔离用户账号或登录态。
- 同一页面多个 Widget 实例支持（仍维持 `chat-widget-embeddable-js.md` 中的排除项）。
- 按频道统计 Widget 使用量或流量分析。
- Widget 版本管理与 CDN 分发策略。
- 宿主页面向 Widget 发送消息（postMessage 等双向通信）。
- 按频道维度而非全局维度的 CORS 策略。

### 2.3 依赖项

- **Widget 嵌入能力**：依赖 `docs/prd/integration/chat-widget-embeddable-js.md` 已实现的全局初始化接口与 Shadow DOM 渲染。
- **API Token 鉴权**：依赖 `docs/prd/infrastructure/api-token-auth.md` 保护文档管理、运营数据查看等管理操作。
- **现有聊天与文档能力**：聊天、文档上传/发布/删除、反馈、低相关召回记录等能力需识别并校验 `channelId`。
- **配置文件解析**：需要新增频道定义段，并支持每个频道的子配置。

## 3. 需求概述

### 3.1 功能描述

让 RWiki 能够同时服务多个独立频道。每个频道对应一个 `channelId`，拥有自己的知识库文档、聊天上下文、反馈记录和聊天行为配置。Admin 通过配置文件声明所有合法频道；Website Integrator 在 Widget 初始化时传入频道；普通用户则通过主站 URL 后缀访问对应频道。全局 CORS 配置继续控制哪些第三方域名允许跨域调用，所有频道共享这一层安全策略。

### 3.2 关键特性

- **频道静态定义**：频道在配置文件中声明，服务启动时加载，不允许运行时任意创建。
- **全数据隔离**：文档、分块、发布状态、聊天会话、反馈、低相关召回记录、推荐问题、系统提示词均按 `channelId` 隔离。
- **双入口传递 channelId**：Widget 通过初始化配置；主站前端通过 URL path。
- **强制 channelId**：缺少或非法的 `channelId` 直接拒绝，不回退到共享默认知识库。
- **全局 CORS 共享**：一份 allowed origins 列表约束所有频道的浏览器跨域来源。
- **频道级配置覆盖**：频道级系统提示词、推荐问题覆盖全局默认值；未配置时回退全局默认。

## 4. 业务规则与状态

### 4.1 业务规则

- **频道定义来源**：仅配置文件；运行时不可通过 API 创建新频道。
- **channelId 唯一性**：配置文件中不允许出现重复 `channelId`，否则服务启动失败。
- **channelId 格式**：由 Admin 定义，使用 URL-safe 字符串（字母、数字、连字符、下划线）。
- **强制携带 channelId**：所有频道相关请求必须携带有效 `channelId`；缺失或未知时返回错误，不渲染、不回答。
- **数据隔离边界**：
  - 文档上传、列表、删除、发布/取消发布仅影响所属频道。
  - 检索与聊天上下文仅在所属频道的已发布文档集合中召回。
  - 反馈、低相关召回记录仅记录到所属频道，查询时按频道过滤。
  - 系统提示词、推荐问题按频道读取。
  - 相同会话 ID 在不同频道下不复用历史上下文。
- **CORS 策略**：沿用全局 `allowed_origins`；空列表表示允许所有来源（向后兼容 CORS 行为，但不兼容无 `channelId` 的旧请求）。
- **频道配置优先级**：频道级系统提示词与推荐问题覆盖全局默认；未配置频道级参数时回退到全局默认值。
- **频道推荐问题强控**：一旦频道已配置推荐问题，Widget 初始化传入的本地推荐问题配置被忽略，统一以服务端频道配置为准。
- **跨频道操作安全**：管理操作在所属频道维度校验归属，跨频道文档 ID 按不存在处理，避免通过 ID 枚举其他频道内容。

### 4.2 关键状态与异常

- **频道正常**：请求携带的 `channelId` 在配置中已定义 → 正常处理。
- **频道不存在**：`channelId` 未定义 → 拒绝请求，返回"频道不存在或不可用"。
- **channelId 缺失**：请求未携带 `channelId` → 拒绝请求，返回"缺少 channelId"。
- **频道无可用内容**：频道范围内无已发布文档 → 拒绝聊天请求并提示当前频道没有可用文档。
- **配置加载失败**：重复 `channelId`、未配置任何频道等 → 服务启动失败并给出明确错误。
- **历史数据未回填**：数据库存在未归属频道的内容 → 服务启动失败并提示运营方先回填。
- **CORS 拒绝**：来源不在全局 `allowed_origins` 中 → 浏览器阻止跨域请求，Widget 显示连接失败提示。

## 5. 功能需求

### 5.1 核心需求

1. **频道定义配置**
   - 配置文件支持声明多个频道，每个频道至少包含 `channelId` 与人类可读名称。
   - 可选频道级配置：系统提示词、推荐问题（按语言分组）等。
   - 启动时校验 `channelId` 唯一性、格式，并要求至少存在一个频道。

2. **channelId 传递机制**
   - Widget 侧：初始化时频道标识为必填项，缺失时不渲染组件。
   - 主站前端：通过 URL path 后缀声明频道，未知频道显示错误页且不发起任何聊天、推荐问题或反馈请求。
   - 管理后台：运营选定频道后，文档上传、列表、发布、批处理、低相关记录查看均限定该频道。

3. **全链路数据隔离**
   - 文档与分块的存储、检索、列表、删除均按 `channelId` 过滤。
   - 聊天在指定频道的已发布文档集合中执行 RAG，会话上下文绑定到 `channelId`。
   - 反馈、低相关召回记录写入时带上 `channelId`，查询时按 `channelId` 过滤。
   - 频道级配置（系统提示词、推荐问题）按 `channelId` 读取，未配置时回退全局默认。

4. **全局 CORS**
   - 继续使用全局 `allowed_origins`。
   - 空列表时允许所有来源（保持现有 CORS 默认行为）。
   - 非空列表时仅允许匹配的 origin 跨域访问任意已配置频道。

5. **错误与提示**
   - 缺少 `channelId`：Widget 初始化报错，主站显示错误页，接口返回错误。
   - 未知 `channelId`：提示"频道不存在或不可用"。
   - 频道无可用文档：聊天请求被拒绝并提示当前频道没有可用文档。
   - CORS 拒绝：沿用 Widget 现有"无法连接服务"提示。

### 5.2 验收目标

- 配置文件中定义两个频道后，两个频道可以分别上传不同文档并独立检索。
- Widget 用某频道初始化的访客只能获得该频道知识库的回答。
- 通过主站 URL 后缀访问某频道的用户只能获得该频道知识库的回答。
- 未传频道标识的 Widget 不渲染并提示必填。
- 访问未配置频道的主站 URL 时页面提示频道不存在，且不发起任何聊天相关请求。
- 管理后台切换频道后，文档列表、上传、批处理、低相关记录均限定当前频道。
- 全局 `allowed_origins` 配置生效，未授权域名无法跨域调用任何频道。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：现有聊天、文档、反馈、低相关召回等能力均识别 `channelId` 并按频道过滤；不新增面向频道管理的运行时接口（频道仅在配置中定义）。频道列表查询为公开能力，仅返回频道标识与名称，不暴露提示词或文档内容。
- **访问控制原则**：`channelId` 是频道数据隔离的第一道边界；全局 CORS 是浏览器跨域来源的第二道边界；管理类操作仍受 API Token 保护。`channelId` 为公开标识，不用于鉴权。
- **兼容性说明**：本能力是破坏性变更——旧请求（无 `channelId`）将被拒绝，旧 Widget 集成因未传 `channelId` 将初始化失败，主站根路径不再作为无频道聊天入口。升级前必须人工回填或重建历史数据。
- **相关接口说明或设计文档位置**：接口级别的 `channelId` 提取、透传与隔离实现细节由 `docs/design` 与技术设计文档承载，不写入本 PRD。

## 7. 前端/交互约束

**适用性**: 适用

### 7.1 页面入口

- **Widget 入口**：第三方页面通过 `<script>` 引入 Widget 资源，初始化时传入 API 地址与目标频道。
- **主站入口**：浏览器通过带频道标识的 URL path 打开对应频道聊天页；根路径仅作为频道入口列表或引导，不承载无频道聊天。
- **管理后台入口**：Admin 通过受保护界面查看频道列表与当前选定频道的运营数据（频道定义本身只读，来自配置文件）。

### 7.2 关键交互

- **Widget 初始化**：频道标识必填；缺失时控制台报错，不渲染组件。
- **主站 URL**：频道 path 后缀作为频道路由；未知频道显示错误页且不发起聊天、推荐问题或反馈请求。
- **管理后台**：运营可切换查看不同频道的文档、反馈、低相关召回记录等运营数据；切换后相关列表与操作限定当前频道。频道选择为全局控件，非每次上传独立选择。

### 7.3 状态反馈

- **频道正常**：页面/Widget 正常加载，聊天基于该频道知识库回答。
- **channelId 缺失**：Widget 控制台报错；主站显示"缺少 channelId"。
- **频道不存在**：Widget 发送问题后提示"频道不存在或不可用"；主站显示对应错误页。
- **频道无可用文档**：聊天请求被拒绝并提示当前频道没有可用文档。
- **CORS 拒绝**：Widget 沿用"无法连接服务，请检查配置或稍后重试"。

## 8. 已确认决策

- **多频道数据隔离**：引入 `channelId` 作为频道唯一标识，覆盖 `01-product-overview.md` 中的"多租户/多知识库隔离"非目标。
- **频道静态定义**：仅通过配置文件声明频道，不允许运行时创建。
- **channelId 必填**：所有频道相关请求必须携带有效 `channelId`；缺失或未知均拒绝。
- **双入口传递**：Widget 通过初始化配置项；主站通过 URL path 后缀。
- **全数据隔离**：文档、分块、发布状态、聊天上下文、反馈、低相关召回记录、推荐问题、系统提示词均按 `channelId` 隔离。
- **频道级配置覆盖**：频道级系统提示词、推荐问题覆盖全局默认；未配置时回退全局默认。
- **频道推荐问题强控**：频道配置推荐问题后，Widget 本地推荐问题配置被忽略。
- **全局 CORS**：`allowed_origins` 为全局共享策略，不随频道变化。
- **不自动迁移历史数据**：已有无 `channelId` 的历史数据不在运行时自动归属，升级前需运营方人工规划回填（破坏性变更）。

## 9. 风险与待确认事项

| 风险项 | 等级 | 说明 |
|---|---|---|
| 旧 Widget 集成因未传 `channelId` 全部失效 | P1 | 破坏性变更；需在更新日志与部署文档中明确标注，并提供迁移示例。 |
| 频道配置与历史数据 `channelId` 不同步 | P1 | 删除频道配置但内容仍带旧 `channelId` 时，启动校验应明确提示；该内容不可达但不泄漏到其他频道。 |
| 历史数据 `channelId` 为空导致启动失败 | P1 | 部署前需提供回填操作说明；启动失败提示须明确。 |
| 主站根路径不再是聊天入口 | P2 | 在集成文档和错误页中明确访问格式，并在频道列表可用时提供跳转入口。 |
| 频道推荐问题为空时 Widget 空态无引导 | P2 | 保留欢迎语；空数组时仅显示输入框。 |
