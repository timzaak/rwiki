## 2. 范围界定

### 2.1 包含功能

- **MCP 服务端能力**：在现有单二进制服务内提供 MCP 协议入口（仅 Streamable HTTP 传输形态），供 MCP 客户端（Claude Code、Cursor 等 Agent 工具）远程连接，不引入第二个进程。
- **知识库问答工具**：面向 Agent 的 RAG 问答，返回带来源引用的非流式完整回答；检索范围与回答口径和公开聊天能力一致（查询改写、混合检索、rerank、引用）。
- **知识检索工具**：返回与查询相关的、按相关性排序的原始知识片段列表，每条片段带来源信息。
- **频道隔离**：工具调用必须携带 `channelId`，校验与数据隔离语义和公开聊天能力一致。
- **鉴权整合**：MCP 能力整体复用现有 API Token（Bearer）鉴权与可选来源 IP 白名单，未配置 Token 时服务拒绝启动的既有规则不变。
- **配置管理**：通过配置文件控制 MCP 能力启用，省略配置段即关闭。

### 2.2 不包含功能 (Out of Scope)

- stdio 子进程传输模式。
- MCP OAuth、动态客户端注册等 MCP 原生鉴权机制（沿用 API Token 边界）。
- 流式回答或工具执行进度通知（MCP 工具调用返回单结果）。
- 服务端多轮会话记忆（MCP 问答工具每次调用独立，不存储对话历史）。
- 文档管理操作（上传、列表、删除、发布/取消发布）暴露为 MCP 工具。
- 聊天反馈（赞/踩）、推荐问题等其余聊天能力的 MCP 暴露。
- 前端页面或管理后台变更。
- MCP 客户端侧的接入文档与分发（随使用文档发布，不属产品能力范围）。

### 2.3 依赖项

- **API Token 鉴权**：依赖 `docs/prd/infrastructure/api-token-auth.md` 的鉴权边界，MCP 入口落在受保护范围内。
- **多频道隔离**：依赖 `docs/prd/integration/support-multiple-website.md` 的 `channelId` 校验与数据隔离规则。
- **检索与回答管线**：依赖既有聊天能力基线——查询改写（`docs/prd/chat/query-rewrite.md`）、关键词与混合检索（`docs/prd/document/keyword-search-support.md`）、rerank 精排（`docs/prd/core/rerank-investigation.md`）、上下文组装与引用（`docs/prd/chat/chat-context-prompt-assembly.md`）。

## 3. 需求概述

### 3.1 功能描述

RWiki 的知识库目前只能供人通过 Web 页面或嵌入 Widget 使用。本功能把知识库问答与检索能力以 MCP（Model Context Protocol）工具的形式暴露，使 Claude Code、Cursor 等 Agent 工具可以持 API Token 远程接入，把 RWiki 变成 Agent 可直接调用的知识库工具。知识库从「给人用的问答服务」扩展为「给 Agent 用的工具服务」，扩大同一知识资产的消费面，不改变现有任何用户可见行为。

### 3.2 关键特性

- **只读工具面**：仅暴露问答与检索两个只读工具，管理操作不进入 MCP 工具清单。
- **单服务挂载**：MCP 能力内嵌于现有服务，启用后随服务一起可用，无独立部署单元。
- **回答口径一致**：MCP 问答与公开聊天使用同一检索与回答管线，同一问题在同一频道得到同源回答与引用。
- **默认关闭**：未配置 MCP 段的部署完全不暴露该能力。

## 4. 业务规则与状态

### 4.1 业务规则

- **鉴权规则**：MCP 能力整体受 API Token 保护；Token 缺失、无效或来源 IP 不在白名单时拒绝访问，且不区分具体原因（沿用 `api-token-auth.md` 规则）。
- **工具面边界**：MCP 工具清单仅含知识库问答与知识检索；工具调用均为只读，不产生知识库内容变更、不写入会话反馈。
- **频道规则**：工具调用必须携带有效 `channelId`；缺失、未定义均拒绝，不回退到任何默认频道；检索与问答仅发生在该频道的已发布文档集合内；跨频道内容不可见、不可枚举。
- **回答形态**：问答工具返回一段完整非流式回答，来源引用仅指向该频道已发布文档；检索工具返回按相关性排序的片段列表，每条带来源信息。
- **单轮语义**：每次工具调用独立完成，服务端不保存 MCP 调用之间的对话历史。
- **启用规则**：MCP 能力由配置段控制，配置段存在即启用，省略即关闭；关闭时不影响现有任何能力。
- **异常口径**：频道无已发布文档、频道标识无效等业务异常沿用公开聊天能力的既有提示口径。

### 4.2 关键状态与异常

- **能力未启用**：配置省略 MCP 段 → MCP 入口不可用，服务其余功能正常。
- **鉴权失败**：Token 缺失/无效或来源 IP 不允许 → 拒绝访问，不返回任何知识库内容。
- **正常调用**：频道有效且有已发布文档 → 返回回答或片段列表。
- **频道标识缺失/未定义**：拒绝调用并提示频道不存在或不可用。
- **频道无可用文档**：拒绝问答调用并提示当前频道没有可用文档。
- **检索无相关内容**：返回空结果并正常结束，不视为错误。

## 5. 功能需求

### 5.1 核心需求

1. **MCP 服务端能力**
   - 支持主流 MCP 客户端以 Streamable HTTP 远程连接，完成协议握手。
   - 支持工具发现：客户端可列出 RWiki 提供的工具及用途说明。
   - 支持工具调用：客户端可调用问答与检索工具并获得结果。

2. **知识库问答工具**
   - 入参为问题与目标 `channelId`。
   - 在该频道已发布文档集合内执行检索增强问答，返回带来源引用的完整回答。
   - 业务异常（频道无效、频道无文档）返回明确提示。

3. **知识检索工具**
   - 入参为查询与目标 `channelId`。
   - 返回按相关性排序的原始知识片段列表，每条片段带来源信息，仅来自该频道已发布文档。
   - 无相关内容时返回空结果。

4. **鉴权与访问控制**
   - MCP 能力整体纳入现有 API Token 鉴权与 IP 白名单边界。
   - 鉴权失败的连接与调用一律拒绝。

5. **配置管理**
   - 配置文件提供 MCP 配置段，控制能力启用；沿用项目「省略即关闭」的配置段惯例。
   - 配置项细节由技术设计文档承载，不写入本 PRD。

### 5.2 验收目标

- 配置启用后，MCP 客户端可连接并发现问答与检索两个工具；配置省略时 MCP 入口不可用且现有功能不受影响。
- 无 Token 或无效 Token 的连接与工具调用被拒绝，不返回知识库内容。
- 问答工具对指定频道问题返回带引用的完整回答，引用仅指向该频道已发布文档；与公开聊天能力在同频道同问题上的检索范围口径一致。
- 检索工具返回带来源的排序片段；无相关内容时返回空结果。
- `channelId` 缺失或未定义的调用被拒绝并返回明确提示；频道无已发布文档时问答返回明确提示。
- MCP 调用之间不存在服务端保留的对话历史（重复调用互不影响）。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：以 MCP 协议暴露两个只读工具（知识库问答、知识检索）及标准工具发现能力；不暴露文档管理与反馈类操作。
- **访问控制原则**：MCP 能力整体受现有 API Token（Bearer）与可选 IP 白名单保护，与文档管理接口同一鉴权边界；不引入 MCP OAuth。
- **数据边界**：`channelId` 是 MCP 工具调用的频道数据隔离边界，语义与公开聊天能力一致；`channelId` 为公开标识，不用于鉴权。
- **兼容性要求**：MCP 能力仅以 Streamable HTTP 传输形态提供；现有公开聊天、Widget、文档管理接口行为不变。
- **接口细节**：MCP 入口路径、工具参数与返回结构由技术设计文档承载，不写入本 PRD。

---

## 7. 前端/交互约束

**适用性**: 不适用

本功能为纯后端集成能力，调用方是 MCP 客户端（Agent 工具），无前端页面、组件或交互变更。

---

## 8. 已确认决策

- **仅 Streamable HTTP 传输**：MCP 端点挂载于现有单二进制服务，复用 API Token（Bearer）鉴权与可选 IP 白名单；不提供 stdio 子进程模式。
- **首版单轮语义**：MCP 问答工具每次调用独立完成，服务端不存储 MCP 调用之间的对话历史；多轮会话记忆与流式回答不在当前范围，用户提出相关需求时重开决策。
