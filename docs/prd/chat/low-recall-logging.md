## 2. 范围界定

### 2.1 包含功能

- **自动记录低相关召回查询**：用户提问后，若检索内容相关性低于阈值，旁路记录该查询（含原始问题、相关度分数、召回来源关联、时间）。
- **记录列表与筛选（鉴权）**：提供带 Bearer Token 鉴权的记录查询，支持按分数区间和时间筛选。
- **最小运营页**：列表 + 按分数/时间筛选，复用现有文档管理后台（batch-refresh）的 Admin 模式与 API Key 登录。
- **阈值可配置**：阈值作为可配置项，提供默认值，默认值待从首批记录校准。
- **功能可开关**：整个记录功能可通过配置项启用/禁用。

### 2.2 不包含功能 (Out of Scope)

- **阈值调优 UI**：不在本功能提供调优界面。
- **分析 / 统计看板**：不提供聚合分析或可视化看板。
- **低分查询聚类 + 文档缺口推荐**：列为扩展项，须先过信号质量门禁（见 §5.2），再重新进入决策显式确认。
- **改变实时回答行为**：记录必须旁路，与 chat 管线解耦，不影响回答内容与延迟。

### 2.3 依赖项

- **Rerank 精排**（`docs/prd/core/rerank-investigation.md`）：提供可比较的相关度分数，作为相关性判定依据。
- **API Token 鉴权**（`docs/prd/infrastructure/api-token-auth.md`）：记录查询的访问控制。
- **文档管理后台（batch-refresh）**（`docs/prd/core/batch-refresh.md`）：复用其 Admin 后台框架与 API Key 登录模式。
- **Chat 管线**：记录的触发点（查询检索后旁路写入）。

## 3. 需求概述

### 3.1 功能描述

运营者需要发现"知识库在哪些问题上答不好"，并优先决定补哪篇文档、修哪个分块。现有信号覆盖不全：

- **chat-feedback（赞/踩）**：人工、稀疏，多数答不好的问题无人主动标记；
- **eval 端点**：离线、批量，需手动构造评测集并运行评估，非实时、非全量。

本功能补上第三类信号——**自动、全量、实时旁路**：每条查询检索后，若相关性低于阈值，旁路记录该查询，运营者在管理后台按分数与时间查看筛选，据此发现知识库盲区。三者互补，各覆盖不同盲区，互不重叠。

范围锁定在最小集：仅记录 + 鉴权查询 + 最小运营页。任何扩展（聚类推荐、看板、阈值调优 UI）必须先过信号质量门禁（见 §5.2），再重新进入决策显式确认。

### 3.2 关键特性

- **自动全量旁路记录**：不依赖用户主动反馈，覆盖每条低相关召回查询。
- **运营页列表 + 筛选**：复用现有 Admin 后台模式，运营者可直接使用。
- **阈值可配置**：默认值上线后从首批记录校准（相关度分数分布上线前未知）。
- **与实时回答解耦**：记录旁路，不影响回答内容与延迟。

## 4. 业务规则与状态

### 4.1 业务规则

- **功能开关**：整个记录功能通过配置项启用/禁用；禁用时不产生任何低相关召回记录，启用/禁用均不影响实时回答。运营页可查看历史记录，禁用期间列表不再增长。
- **记录触发**：当一次查询检索的相关性低于阈值时，旁路生成一条记录，至少包含原始问题、相关度分数、召回来源关联与时间。
- **仅记录线上公开知识库提问**：只记录线上公开知识库（Published 作用域）的提问；对草稿批次 / scoped 评测提问不记录——后者不是线上知识库盲区，混入会污染运营视图。
- **完全未命中无条件记录**：检索零召回（无任何结果）的提问作为最强盲区信号无条件记录，相关度记为未命中。
- **记录不含助手回答**：记录发生在检索完成时，仅含提问、相关度分数、召回来源关联与时间，不含助手回答内容（数据最小化）。
- **旁路解耦**：记录写入是旁路行为，不影响实时回答的内容、可用性与延迟；记录写入失败不得阻塞 chat 回答。
- **鉴权复用**：记录查询受 Bearer Token 鉴权保护（与文档管理、反馈查询一致）；运营页复用现有 API Key 登录，不引入 session、用户表或多角色账户体系。
- **阈值机制**：阈值为可配置项，提供默认值；因相关度分数分布上线前未知，默认值粗糙，上线后从首批记录校准（不提供阈值调优 UI）。
- **数据用途**：记录仅用于知识库质量分析与盲区发现，不用于改变实时回答行为。
- **数据保留**：低相关召回记录永久保留，不设 TTL、不自动清理；历史记录始终可查询与筛选（即便功能被禁用，已产生的记录仍保留可查）。
- **三者互补边界**：本功能（自动全量实时信号）与 chat-feedback（人工稀疏信号）、eval（离线批量评测）互补不重叠；不得把三者职责合并或互相替代。

### 4.2 关键状态与异常

- **阈值默认 / 未校准**：上线初期使用默认阈值记录；运营者从首批记录人工复查后校准（信号质量门禁复查，见 §5.2）。
- **记录写入失败**：旁路失败不阻塞 chat 回答；失败不向终端用户暴露。
- **无低分记录**：一段时间内无查询低于阈值时，运营页列表为空并提示暂无记录。
- **API Key 失效**：运营页请求被拒绝并引导回登录页重新输入 Key。

## 5. 功能需求

### 5.1 核心需求

1. **自动记录低相关召回查询**
   - 查询检索后，相关性低于阈值的查询被旁路记录，包含原始问题、相关度分数、召回来源关联与时间。
   - 仅记录线上公开知识库提问；完全未命中无条件记录；记录不含助手回答。
   - 记录不影响实时回答。

2. **记录列表与筛选（鉴权）**
   - 提供受 Bearer Token 鉴权的记录查询，支持按分数区间与时间筛选。
   - 结果可被运营页消费。

3. **最小运营页**
   - 复用现有文档管理后台的 Admin 模式与 API Key 登录。
   - 提供低相关召回记录列表（原始问题、相关度分数、时间、召回来源关联）+ 按分数/时间筛选。

4. **阈值可配置**
   - 阈值为可配置项并带默认值；不提供阈值调优 UI（Out of Scope）。

5. **功能开关**
   - 整个记录功能可通过配置项启用/禁用；禁用时不产生记录，不影响实时回答。

### 5.2 验收目标

- **功能成功标准**：运营者能在管理后台查看低相关召回记录、按分数与时间筛选，并据此发现 / 优先知识库盲区。
- 记录为旁路，实时回答的内容、可用性与延迟不受影响；记录写入失败不阻塞 chat 回答。
- 仅记录线上公开知识库提问；完全未命中被无条件记录；记录不含助手回答。
- 未登录或 API Key 失效时无法查看记录，被引导回登录页。
- 阈值可配置，默认值上线后可从首批记录校准。
- 功能可通过配置项启用/禁用；禁用时不产生低相关召回记录，且不影响实时回答。
- **信号质量门禁（扩展前置）**：运营者复查首批 N 条低分记录后，真正属于"知识库盲区 / 可补内容"的比例须 ≥ 30%，方可推进任何扩展（聚类推荐 / 看板 / 调优 UI）；若 < 30%（即 >70% 为噪声或其实可答），则放弃扩展（搁置或驳回），重新进入决策评估。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：低相关召回记录的自动写入，以及记录列表/筛选查询；查询受 Bearer Token 鉴权保护，与现有文档管理 / 反馈查询一致。
- **访问控制**：复用现有 API Token；前端在浏览器持有 Key 并随请求携带。不引入 session、用户表或多角色账户体系。
- **数据边界**：单一知识库；无多租户、无 realm 分片。
- **兼容性**：记录为旁路，不改变 chat 接口的请求/响应契约；运营页与记录查询为叠加层。

---

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：复用现有文档管理后台入口（API Key 登录后可访问）；在后台内提供低相关召回记录列表页，未登录重定向到登录页。
- **关键交互**：
  - 记录列表：展示原始问题、相关度分数、时间、召回来源关联。
  - 筛选：按分数区间、按时间段筛选。
  - 分页：列表分页加载，避免一次性返回大量记录。
- **状态反馈**：记录加载状态、空列表（暂无低相关召回记录）提示、筛选结果。
- **权限可见性**：运营页全程要求有效 API Key；Key 失效时操作被拒并引导重新登录。
- **不提供**：阈值调优 UI、分析/统计看板（Out of Scope）。

## 8. 已确认决策

- **改名 low-recall-logging**：避免与聊天反馈功能同名冲突，以独立名建立可追溯性。
- **不改变实时回答行为**：仅记录分析，记录旁路、与 chat 管线解耦。
- **仅记录线上公开知识库提问**：草稿批次 / scoped 评测提问不记录，避免污染线上盲区视图。
- **完全未命中无条件记录**：零召回是最强盲区信号，恒记录。
- **记录不含助手回答**：记录发生在检索完成时，数据最小化。
- **阈值机制**：可配置默认值，从首批记录校准（相关度分布上线前未知）。
- **鉴权**：记录查询端点需 Bearer Token，与文档管理 / 反馈查询一致。
- **功能可配置项开关**：整个记录功能可通过配置项启用/禁用；禁用时不记录，不影响实时回答。
- **三者互补边界**：自动全量信号（本功能）/ 人工稀疏信号（chat-feedback）/ 离线评测（eval）互补不重叠。
- **范围锁定最小集**：扩展项（阈值调优 UI、分析/统计看板、低分查询聚类 + 文档缺口推荐）须先过信号质量门禁（§5.2），再重新进入决策显式确认。
