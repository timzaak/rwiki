## 2. 范围界定

### 2.1 包含功能

- 功能可选、默认关闭：由后端单一总开关 `enable_post_answer_suggestions` 控制（默认 false）；主站与嵌入 Widget 共用同一聊天通道，均随该开关，不新增 Widget 侧 opt-in 字段
- 总开关开启后，每条 assistant 回答完成后，在回答内容下方、反馈按钮上方展示最多 3 条后续推荐问题
- 推荐问题基于本轮用户问题、最终回答和本轮检索到的知识库上下文动态生成
- 推荐问题通过现有聊天回答流随本轮回答一次性交付
- 点击任一推荐问题等同于手动发送该问题，复用现有聊天发送流程继续对话
- 主站（独立聊天页 + 浮动弹窗）和嵌入 Widget 在总开关开启时均展示后续推荐问题，行为一致

### 2.2 不包含功能 (Out of Scope)

- 推荐问题数量的运行时配置（固定最多 3 条，不开放配置项）
- 推荐问题持久化到数据库或写入后端会话历史
- 推荐问题点击/使用数据的统计与分析
- 推荐问题的人工管理界面或人工编辑
- pre-question 静态推荐按钮（见 `docs/prd/chat/pre-question-suggested-buttons.md`，两者相互独立）
- 新增独立 REST 端点获取推荐问题
- 推荐问题进入后续多轮检索或查询改写的历史上下文
- 主站与 Widget 的独立开关控制（采用单一后端总开关，两者均随该开关；独立控制可作为后续 fast-follow）

### 2.3 依赖项

- 现有 SSE 流式聊天回答能力（`docs/prd/chat/chat-assistant.md`）
- 现有多轮对话与记忆能力（`docs/prd/chat/multi-turn-conversation-hybrid-memory.md`）
- 现有 OpenAI 兼容 LLM Provider（`docs/prd/infrastructure/model-providers.md`）
- 现有聊天发送/渲染组件与 Widget 嵌入能力（`docs/prd/integration/chat-widget-embeddable-js.md`）

## 3. 需求概述

### 3.1 功能描述

在用户通过 RAG 聊天得到回答后，系统自动基于本轮用户问题、最终回答和本轮检索到的知识库内容，推荐若干个可继续追问的问题，渲染为可点击按钮。用户无需自行构思下一句，点击即可继续深入对话，帮助用户理解系统能回答的范围，并降低连续追问的门槛。

### 3.2 关键特性

- **基于上下文动态生成**：使用本轮用户问题、最终回答和检索到的知识库内容，避免脱离知识库的空泛推荐
- **回答后展示**：仅在对应回答完成后展示，回答生成中不展示
- **点击直接续聊**：复用现有发送流程，不跳转、不另起会话
- **失败静默**：推荐生成失败或超时不打断主回答，前端不展示错误

## 4. 业务规则与状态

### 4.1 业务规则

- **功能开关（可选）**：功能默认关闭。由后端单一总开关 `enable_post_answer_suggestions` 控制；主站与嵌入 Widget 共用聊天通道，均随该开关。开关关闭时不生成、不展示推荐问题，且不为此发起额外的推荐生成 LLM 调用
- **展示时机**：仅当总开关已开启、对应 assistant 回答已完成（非流式生成中）且成功生成出推荐问题时展示
- **展示位置**：在回答内容下方、赞/踩反馈按钮上方；最多 3 条
- **内容来源**：必须基于本轮用户问题、最终回答和本轮检索到的知识库上下文生成；不重复用户本轮已问的问题，不推荐本轮回答已完整覆盖的问题
- **数量上限**：最多 3 条；不足 3 条时展示实际生成数量，可为 0（不展示该区域）
- **点击行为**：点击任一推荐问题等同于手动输入并发送该问题，复用现有聊天回答流程
- **与 pre-question 的关系**：pre-question 仅在空状态展示静态配置按钮；post-answer 仅在回答后展示动态生成问题；两者不共享静态推荐配置，互不干扰；两者同样采用「可选、配置驱动」模式（未配置/未开启即不展示）
- **会话归属**：推荐问题作为对应历史回答的一部分保留在对话视觉中；不进入后端会话历史，不参与后续检索或改写

### 4.2 关键状态与异常

- **功能关闭（总开关 off）**：主站与 Widget 均不生成、不展示推荐问题区域，回答正常完成，且不发起额外的推荐生成 LLM 调用
- **推荐生成失败/超时**：不展示推荐问题区域，回答正常完成，用户无错误感知
- **主回答失败**：不生成推荐问题，不展示推荐区域
- **历史消息中的推荐问题**：刷新或重新打开会话后，历史回答上的推荐问题作为该回答的一部分保留可接受；点击仍可发送
- **无 assistant 回答**：不触发推荐展示

## 5. 功能需求

### 5.1 核心需求

1. **可选开关（默认关闭）**
   - 由后端单一总开关 `enable_post_answer_suggestions` 控制；主站与嵌入 Widget 共用聊天通道，均随该开关
   - 开关闭时不展示、不生成推荐问题，且不为此发起额外的推荐生成 LLM 调用

2. **动态推荐生成**
   - 在主回答完成后，基于本轮用户问题、最终回答和本轮检索到的知识库上下文生成后续推荐问题
   - 固定最多 3 条

3. **随本轮回答交付**
   - 推荐问题随本次聊天回答流一次性交付，在回答完成、结束事件之前发送
   - 不新增独立请求获取推荐问题

4. **前端展示**
   - 在每条已完成的 assistant 回答内容下方、反馈按钮上方渲染推荐问题按钮
   - 回答生成中不渲染；推荐为空时不渲染该区域

5. **点击续聊**
   - 点击推荐问题复用现有发送流程，将该问题作为新的一轮发送

6. **双入口随总开关一致**
   - 主站（独立聊天页 + 浮动弹窗）和嵌入 Widget 在总开关开启后均展示后续推荐问题，行为一致
   - 推荐承载方式兼容现有事件识别，不影响既有事件

### 5.2 验收目标

- 用户每轮收到流式回答完成后，在回答下方看到最多 3 条基于本轮问答与知识库内容的推荐问题
- 推荐问题不重复用户本轮已问的问题，且与本轮回答相关
- 点击任一推荐问题后，该问题被发送并得到正常流式回答，对话继续
- 推荐生成失败或超时时，回答仍正常完成，且不向用户展示任何错误
- 回答正在生成时不展示推荐问题
- Widget 中的回答同样展示后续推荐问题，行为与主站一致
- 总开关关闭时，主站回答下方不展示推荐问题，且系统不为此发起额外的推荐生成调用
- 总开关关闭时，Widget 回答下方不展示推荐问题（Widget 随总开关，无独立 opt-in）

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：复用现有 SSE 聊天回答通道，新增一种 SSE 事件类型承载后续推荐问题；不新增独立 REST 端点，不修改现有请求体
- **访问控制**：沿用现有聊天接口的访问控制（公开访问，与 chat-assistant 一致），推荐问题不引入新的鉴权要求
- **兼容性**：新增事件不影响现有 SSE 事件识别与顺序；推荐问题在回答完成之后、结束事件之前交付；失败时不发送或发送空集合，结束事件仍正常发出

---

## 7. 前端/交互约束

**适用性**: 适用

### 7.1 页面入口

- 落地页 / 独立聊天页的每条 assistant 回答
- 全局浮动弹窗聊天的每条 assistant 回答
- 嵌入 Widget 聊天窗口的每条 assistant 回答

### 7.2 关键交互

- **展示位置**：回答内容下方、赞/踩反馈按钮上方；紧凑排列，最多 3 条
- **点击**：点击推荐问题后该问题进入消息区域作为新一轮发送，复用现有流式回答
- **生成中不展示**：回答生成中不渲染推荐按钮，完成后才出现

### 7.3 状态反馈

- **推荐生成中**：无额外加载态，回答完成后按钮即时出现（或为空时不出现）
- **推荐生成失败**：不出现推荐区域，无错误提示，回答正常完成
- **功能关闭（总开关 off）**：主站与 Widget 均不出现推荐区域，无错误提示，回答正常完成（等同未启用此功能）

## 8. 已确认决策

- **固定最多 3 条**：推荐问题数量固定最多 3 条，不开放运行时配置
- **基于本轮上下文**：推荐必须基于本轮用户问题、最终回答和检索到的知识库内容，避免空泛
- **随回答流交付**：通过现有 SSE 聊天流新增事件一次性交付，不新增独立请求或端点
- **失败静默**：推荐生成失败/超时不影响主回答，前端不展示错误
- **不持久化**：推荐问题不写入数据库或后端会话历史，不参与后续检索或改写
- **可选功能、默认关闭**：由后端单一总开关 `enable_post_answer_suggestions` 控制，主站与 Widget 均随该开关；开关关闭时不展示、不生成、不发起额外 LLM 调用（主站/Widget 独立控制为后续 fast-follow）
- **双入口随总开关一致**：主站与 Widget 在总开关开启后行为一致
- **点击复用发送**：点击推荐问题复用现有聊天发送流程，不跳转、不另起会话
- **不修改 pre-question**：与静态推荐按钮相互独立，不共享配置
