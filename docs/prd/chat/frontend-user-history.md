## 2. 范围界定

### 2.1 包含功能

- 历史会话列表：按时间倒序展示本浏览器中归档的会话，会话条目可辨识（以首条用户提问作为标识），当前查看会话高亮
- 会话来回切换回看：点击列表项在不同历史会话之间来回切换，聊天区域完整显示所选会话的全部问答
- 历史永久保留：会话归档后一直保留在浏览器本地，直到用户手动删除或清空
- 继续对话：打开历史会话后可直接接着提问，新问答追加在该会话内（服务端记忆过期时透明降级，见 §4.1）
- 历史管理：删除单个历史会话、一键清空当前频道全部历史（清空前弹出二次确认对话框）
- 新对话归档：点击"新对话"时当前会话自动进入历史，无需手动保存
- 全入口一致：主站 `/c/$channelId` 频道页浮动弹窗，以及 Widget（弹窗/右侧停靠侧栏两种形态）提供一致的上述能力

### 2.2 不包含功能 (Out of Scope)

- 服务端持久化对话历史、跨设备/跨浏览器同步（历史仅存于用户本地浏览器；后端会话保持纯内存，见 `chat/multi-turn-conversation-hybrid-memory.md`）
- 会话内轮次级回退/前进导航
- 历史会话搜索、重命名、编辑、置顶等管理能力
- 对话导出或分享（沿 `chat/chat-assistant.md` 既有排除项）
- 后端 API、后端多轮记忆机制变更（纯前端行为，sessionId 机制不变）
- 账号体系下的历史归属（本产品当前无用户认证，历史以浏览器本地 + 频道为边界）

### 2.3 依赖项

- 现有前端聊天组件与本地会话存储及其频道隔离机制（channelKey）
- 现有聊天流式接口与 sessionId 透传机制：服务端按内存 TTL 维护多轮上下文（本 PRD 不改变该机制）
- Widget 与主站共享同一聊天实现的基础设施（`integration/chat-widget-embeddable-js.md`）

## 3. 需求概述

### 3.1 功能描述

用户在所有聊天入口产生的会话自动归档并永久保留在浏览器本地（按频道隔离）。用户通过历史会话列表在不同会话之间来回切换回看完整问答，也可打开旧会话继续追问，或删除/清空不需要的历史。知识库问答的答案往往值得反复查阅，历史回看让用户无需重复提问即可复用既往回答。

### 3.2 关键特性

- **自动归档、无需保存**：会话随对话自动进入历史，"新对话"仅开启新会话，不销毁旧内容
- **永久本地保留**：历史不受超时影响，隔日、隔周回访仍可查看，直到用户手动清除
- **来回切换回看**：会话级列表导航，切换即完整回看，操作可任意往返
- **可延续**：历史会话可继续提问；服务端记忆过期时从该轮起重建上下文，对用户透明
- **入口一致**：主站与 Widget 各入口行为完全一致；历史按频道隔离，互不串扰

## 4. 业务规则与状态

### 4.1 业务规则

- **保留规则**：历史会话永久保留于浏览器本地，仅通过用户删除/清空移除
- **归档时机**：会话随对话自动进入历史，不提供显式"保存"动作；"新对话"将当前会话归档后开启新的空会话
- **恢复语义**：页面刷新或聊天面板关闭重开时，恢复最近活跃会话并保持其在历史中的位置
- **频道隔离**：历史会话按频道隔离；切换频道只可见目标频道的历史，切换时中止在途回答、当前会话归档进其频道历史后清空工作区（会话不丢失）
- **继续对话降级**：历史会话续聊时若服务端已不保留其多轮上下文（内存会话过期/服务重启），从该轮起重建上下文正常回答；前端历史完整显示，不向用户暴露错误
- **本地数据边界**：历史仅存于用户本机浏览器，不上传服务端；Widget 场景下即访客自己的浏览器，站点方不获得访客历史
- **删除语义**：删除单个会话直接执行且不可恢复；一键清空需二次确认，清空范围为当前频道的历史归档（与列表可见范围一致，其他频道历史保留，确认对话框明确说明范围），且不清除用户当前正在进行、正在查看的对话
- **存储配额**：本地存储写入失败（如配额溢出）不得中断聊天主流程；历史写入失败时向用户提示并可引导清理

### 4.2 关键状态与异常

- **本地存储不可用**（受限嵌入环境等）：聊天正常可用，不提供历史入口或列表为空态，不报错（沿 Widget 静默降级模式）
- **空历史**：首次使用或全部清除后，列表显示空状态提示，非错误
- **续聊时服务端记忆过期**：见 §4.1"继续对话降级"，用户可感知的仅是回答不带更早上下文，无错误提示
- **删除后回看**：已删除会话从列表移除，不可再达；其余会话不受影响

## 5. 功能需求

### 5.1 核心需求

1. **历史会话列表**
   - 所有聊天面板提供历史入口，打开后按时间倒序展示当前频道的归档会话
   - 每个条目展示可辨识的会话标识（首条用户提问摘要）与时间信息，当前查看会话高亮且不可删除

2. **会话切换回看**
   - 点击列表项即在聊天区域完整显示该会话问答，可任意来回切换
   - 回看为完整内容展示（含既有 Markdown 渲染、引用、反馈状态展示）

3. **继续对话**
   - 历史会话打开时输入框可用，新问答以流式追加在该会话末尾，并更新为最近活跃会话

4. **历史管理**
   - 会话条目级删除：删除后从列表移除且不可恢复
   - 一键清空：入口在历史列表内，执行前弹出二次确认对话框（初始焦点在取消按钮、支持键盘操作）；清空范围为当前频道归档，不含当前对话

5. **新对话归档**
   - "新对话"开启新会话，原会话自动进入历史

6. **全入口一致**
   - 主站 `/c/$channelId` 频道页浮动弹窗与 Widget（弹窗/侧栏）提供一致的历史能力与交互

### 5.2 验收目标

- 完成一轮问答 → 点击"新对话" → 历史列表出现该会话，点击可回看完整问答，来回切换内容不丢失
- 完全关闭浏览器后重开（或刷新页面），历史会话列表完整保留、内容可回看
- 在已归档多日的会话中继续提问，能正常收到流式回答且前端历史完整，无错误提示
- 删除单个会话后该会话不可再回看，其余会话不受影响；清空前弹出二次确认，取消则历史不变
- 频道 A 产生的历史在频道 B 中不可见；清空频道 A 的历史不影响频道 B
- 主站与 Widget 各入口的历史行为一致；本地存储不可用时聊天功能不受影响

## 7. 前端/交互约束

**适用性**: 适用

### 7.1 页面入口

- 主站：`/c/$channelId` 频道页的浮动弹窗聊天
- Widget：第三方宿主页面的弹窗形态与右侧推挤侧栏形态（Shadow DOM 内，不影响宿主页面）
- 历史入口位于各聊天面板内部（与输入区、消息区同层级），不新增独立路由页面

### 7.2 关键交互

- **打开/收起历史列表**：面板内入口开关，列表展开时聊天消息区仍可回看当前会话
- **切换会话**：点击列表项即切换显示；再次点击其他会话可任意往返，当前项高亮
- **继续对话**：在所选历史会话中直接使用输入框发送，Enter 发送、Shift+Enter 换行
- **删除单个会话**：会话条目上的删除操作，直接执行
- **清空全部**：历史列表内的清空入口，弹确认提示，确认后清除本频道历史、取消则不变
- **新对话**：归档当前会话并开启空会话
- **Widget 兼容**：历史列表完全在 Widget Shadow DOM 内渲染，不向宿主页面注入内容；两种显示形态（弹窗/侧栏）下行为一致

### 7.3 状态反馈

- 历史读取为本地即时操作，无加载等待态
- 空历史显示空状态提示；清空操作以确认提示防误触
- 本地存储写入失败时提示用户（不阻断聊天），可引导清理历史
- 续聊时服务端记忆过期不产生任何用户可见的错误或提示
