## 2. 范围界定

### 2.1 包含功能

- 上传 xlsx 文件，系统自动解析并生成向量索引
- 基于已索引文档的多轮对话（保留上下文）
- 流式实时返回回答内容
- 已上传文档的列表查看和删除
- 独立全屏聊天页面
- 页面右下角浮动弹窗聊天（PC 浮窗 / 移动端全屏覆盖）

### 2.2 不包含功能 (Out of Scope)

- 用户认证与鉴权（文档管理接口已通过 API Token 鉴权，详见 `infrastructure/api-token-auth.md`）
- 多知识库管理（MVP 仅单一知识库）
- 未被文档摄入 PRD 明确支持的文件格式（如 PDF、CSV）
- 对话历史持久化（MVP 会话内保留，刷新后不保留）
- 对话导出或分享
- LLM 模型切换（固定使用配置中的模型）
- 多用户 / 多租户隔离
- AI Trace 可观测性（后续迭代）

### 2.3 依赖项

- OpenAI 兼容 LLM Provider（LLM 完成）
- OpenAI API Key（Embedding 向量化）
- SQLite + sqlite-vec（文档元数据和向量统一持久化）

## 3. 需求概述

### 3.1 功能描述

为个人用户提供一个 RAG 驱动的知识库聊天助手。用户上传 xlsx 文件后，系统解析内容并向量化存储。用户通过自然语言提问，系统检索相关文档片段并结合 LLM 生成回答。支持多轮对话，能理解上下文指代。

### 3.2 关键特性

- **xlsx 智能解析**：自动读取表头和数据行，按逻辑单元分块后向量化
- **多轮上下文对话**：支持追问和指代前文，对话内保留完整上下文
- **流式响应**：回答实时逐字显示，降低等待感
- **双模式聊天入口**：独立页面 + 浮动弹窗，满足沉浸查询和快速提问两种场景

## 4. 业务规则与状态

### 4.1 业务规则

- **单知识库**：所有上传的 xlsx 文件内容汇总到同一个知识库，不区分来源文件进行检索
- **诚实回答**：当知识库中没有相关数据时，系统必须明确告知用户，不得编造内容
- **上传格式边界**：基础能力从 xlsx 上传起步；当前支持格式以 `document/document-ingestion.md` 为准
- **数据分块**：xlsx 数据按行分块，Markdown 内容按标题边界分块，默认字符上限 1600，超出部分二次分割
- **会话生命周期**：一次会话的上下文在页面/弹窗打开期间有效，关闭或刷新后清空
- **文档持久化**：文档元数据和向量数据统一存储在 SQLite 中，应用重启后数据保留

### 4.2 关键状态与异常

- **文档状态**：草稿 → 可发布；已发布 → 可被检索；解析失败 → 显示错误原因，不可被检索
- **服务重启**：向量数据持久化在 SQLite 中，重启后自动恢复，无需重新上传
- **LLM 调用失败**：向用户显示"回答生成失败，请稍后重试"，不暴露内部错误细节
- **文件上传失败**：显示具体的失败原因（格式不支持、文件过大、内容为空）

## 5. 功能需求

### 5.1 核心需求

1. **文件上传与解析**
   - 用户通过界面上传 xlsx 文件
   - 系统解析文件内容，将数据分块后调用 Embedding API 向量化
   - 解析完成后更新文档状态

2. **RAG 查询与对话**
   - 用户输入问题，系统检索最相关的文档片段
   - 将检索结果作为上下文发送给 LLM，生成回答
   - 多轮对话保留历史消息作为上下文

3. **流式响应**
   - LLM 回答通过 SSE 实时推送到前端
   - 前端逐字/逐段渲染回答内容

4. **文档管理**
   - 展示已上传文档的列表和状态
   - 支持删除文档（同步清除向量索引）

5. **聊天 UI**
   - 独立全屏聊天页面（含对话历史和输入区）
   - 浮动弹窗聊天（PC 浮窗 / 移动端全屏覆盖）

### 5.2 验收目标

- 用户上传一个有效的 xlsx 文件后，能在 30 秒内完成索引（文件 ≤ 1000 行）
- 用户提问后，2 秒内开始流式输出回答
- 多轮对话中，系统能正确理解"那个月"、"它"等前文指代
- 文档列表正确展示所有已上传文档的状态
- 弹窗关闭后重新打开，对话内容保留

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：文件上传（multipart）、文档列表查询、文档删除、聊天对话（SSE 流式）、健康检查
- **访问控制**：文档管理接口（上传、列表、删除、发布、取消发布）需 Bearer Token 鉴权；聊天和健康检查接口公开访问（详见 `infrastructure/api-token-auth.md`）
- **聊天接口**：使用 SSE 协议推送流式回答
- **文件上传**：接受 multipart/form-data，具体支持格式以文档摄入 PRD 为准

## 7. 前端/交互约束

**适用性**: 适用

### 7.1 页面入口

- `/chat` — 独立全屏聊天页面
- 全局浮动按钮 — 右下角，点击打开弹窗

### 7.2 关键交互

- **文件上传**：通过聊天界面上方的上传区域拖拽或点击选择 xlsx 文件
- **聊天输入**：支持多行文本输入，Enter 发送，Shift+Enter 换行
- **流式渲染**：回答区域实时显示生成内容，支持 Markdown 格式和代码块高亮
- **弹窗切换**：PC 端浮动窗口可拖拽调整位置；移动端自动切换为全屏覆盖模式

### 7.3 状态反馈

- 上传中显示进度指示
- 文档索引中显示"正在处理"状态
- LLM 生成中显示打字动画指示
- 错误时显示明确的用户友好提示

## 8. 已确认决策与待确认假设

### 8.1 已确认决策

- **MVP 范围**：仅 RAG 查询 + 基础聊天 UI + xlsx 上传，AI Trace 后续迭代
- **目标用户**：个人工具，单用户场景，文档管理需 API Token 鉴权
- **知识库模型**：单一知识库，所有文档汇总检索
- **文件格式**：基础 MVP 从 xlsx 开始；当前格式范围由文档摄入 PRD 维护
- **对话模式**：多轮对话，会话级上下文（不持久化对话历史）
- **UI 形态**：独立全屏页面 + 浮动弹窗并存
- **向量存储**：sqlite-vec 持久化存储（SQLite 统一存储）
- **RAG 框架选型**：基于 rig 框架实现 RAG 流程（向量检索 + LLM 生成），预研验证可行
- **LLM 提供商**：OpenAI 兼容 LLM Provider 用于 LLM 完成，OpenAI 用于 Embedding
- **文档元数据**：持久化到 SQLite（文件名、状态、行数等）
- **服务重启恢复**：向量数据持久化在 SQLite 中，重启后自动恢复
- **xlsx 文件大小**：上限 50MB
- **并发限制**：个人使用场景无并发问题，不设限流

（无）
