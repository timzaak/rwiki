## 2. 范围界定

### 2.1 包含功能

- 在 config.toml 中新增 `[chat]` 配置段，包含 `system_prompt` 字段
- 系统提示词分为角色描述层和行为规则层，均可通过配置自定义
- 配置缺失时使用当前硬编码提示词作为默认值，保证向后兼容
- 不同环境（development/demo/production）可使用不同提示词
- RAG 上下文注入保持动态生成，不受配置影响

### 2.2 不包含功能 (Out of Scope)

- 通过 API 接口管理提示词（仅配置文件方式）
- 运行时热更新提示词（仅启动时加载）
- 前端界面配置提示词
- 多提示词模板切换（如按知识库或用户组）
- 提示词版本管理或回滚
- 提示词效果评估或 A/B 测试

### 2.3 依赖项

- 现有配置体系（TOML 配置文件 + 反序列化框架）— 无新依赖
- 现有 LLM 代理接口 — 已在使用的接口，无变更
- 与 chat-assistant PRD 的 RAG 对话流程一致

## 3. 需求概述

### 3.1 功能描述

将当前硬编码在 chat handler 中的系统提示词（角色描述 + 行为规则）外部化到配置文件。管理员可通过修改 config.toml 自定义助手的角色、语气和专业领域，适应不同部署场景。上下文注入（RAG 检索结果拼接）保持代码动态生成，不可配置。

### 3.2 关键特性

- **分层配置**: 角色描述和行为规则可整体配置为一段完整提示词，保持灵活
- **默认值兜底**: 配置缺失时使用当前硬编码值，系统行为不变
- **环境差异化**: 不同部署环境可使用不同提示词（如 demo 环境用简化版，生产环境用完整版）
- **零侵入**: 对前端和 API 完全透明，接口不变

---

## 4. 业务规则与状态

### 4.1 业务规则

- **提示词归属**: 系统提示词属于系统级行为配置，仅管理员通过文件系统修改
- **生效方式**: 修改配置后需重启服务生效
- **安全边界**: 提示词不应包含 API Key 等敏感信息；配置文件权限由操作系统控制
- **默认行为**: 未配置 `system_prompt` 时，使用与当前硬编码一致的默认值：
  - 角色："你是一个知识库助手"
  - 规则：1) 无相关信息时明确告知；2) 引用时标注来源标题和章节；3) 有链接时附上链接；4) 来源标注语言（Locale）时在回答中提及
- **上下文不可配**: RAG 检索结果的注入逻辑保持代码控制，不作为配置项

### 4.2 关键状态与异常

- **配置格式错误**: TOML 解析失败时服务启动失败，日志输出具体错误位置
- **配置值为空字符串**: 等同于未配置，使用默认值
- **提示词过长**: 不做硬性长度限制，受 LLM 模型上下文窗口自然约束

## 5. 功能需求

### 5.1 核心需求

1. **配置结构扩展**
   - 配置文件新增聊天配置段，包含 `system_prompt` 字段
   - `system_prompt` 支持配置缺失时自动使用默认值

2. **提示词模板渲染**
   - 配置中的提示词作为角色和行为层模板
   - 运行时将 RAG 检索上下文拼接到提示词末尾
   - 拼接方式与当前逻辑保持一致

3. **多环境配置**
   - `config.toml`、`config.example.toml`、`demo.toml` 均新增 `[chat]` 段
   - `config.example.toml` 包含完整注释说明各配置项用途

### 5.2 验收目标

- 配置自定义提示词并重启后，助手使用新提示词回答，回答风格符合配置预期
- 删除 `[chat]` 段后重启，助手行为与当前硬编码完全一致
- RAG 检索和来源引用功能不受影响
- 所有现有测试通过，无回归

## 6. API 相关约束

**适用性**: 不适用

本功能不涉及 API 接口变更。聊天接口的请求/响应格式不变，系统提示词的配置仅影响 LLM 的行为，不影响 API 契约。

---

## 7. 前端/交互约束

**适用性**: 不适用

本功能对前端完全透明。前端无需任何变更。

---

## 8. 已确认决策

- **配置方式**: 通过 config.toml 文件配置，不通过 API 或前端界面
- **生效时机**: 服务启动时加载，不支持运行时热更新
- **提示词结构**: 整体配置为一段完整文本，不拆分为多个字段
- **上下文注入**: RAG 检索结果保持代码动态拼接，不可配置
- **向后兼容**: 配置缺失时使用当前硬编码值作为默认值
- **不引入新依赖**: 使用现有配置序列化框架
- **目标域**: `core`（核心系统行为配置）
