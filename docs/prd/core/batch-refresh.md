## 2. 范围界定

### 2.1 包含功能

- **文档管理后台（前端）**：文档列表（文件名、状态、行数、上传时间、错误信息）、文件上传、按状态筛选、行级勾选、批量上线/下线、删除。
- **批量上下线（单次提交）**：用户勾选"上线一批 + 下线一批"后一次提交，两组状态变更在同一请求内一起生效。
- **写入去重自包含**：上传新文档时，即使内容与线上已有文档完全相同，也为该文档建立独立的检索条目（相同内容仅复用向量、不重复向量化），确保下线老文档后未改动内容不丢失。
- **API Key 登录**：运营用系统已有的 API Key 在浏览器登录管理后台。
- **eval 指定文档集合**：评测可限定到一组文档，并支持对尚未上线的草稿批次预演评测。

### 2.2 不包含功能 (Out of Scope)

- **版本分组 / 原子整体替换 / 蓝绿切换 / 检索层 content_hash 折叠**：评估为过度设计，不提供。
- **多用户/角色账户体系、session/cookie 鉴权**：复用单一静态 API Token，不引入用户表与登录态服务。
- **旧版本（草稿）自动清理**：下线的文档保留为草稿，不自动删除。
- **多版本并存检索、并发多版本上传**。

### 2.3 依赖项

- 文档生命周期（`document/document-lifecycle.md`）：`processing/draft/published/failed` 状态机、发布/取消发布/删除的可检索性契约。
- API Token 鉴权（`infrastructure/api-token-auth.md`）：管理后台与文档管理接口的访问控制。
- 文档摄入（`document/document-ingestion.md`）：上传、解析、分块、索引链路。
- eval 端点（内部工程工具）：复用其检索与生成管线。

## 3. 需求概述

### 3.1 功能描述

运营定期刷新 wiki：上传一批新内容（含未改动、修改、新增的混合），需要把新批次切换为线上、同时下线老批次，且切换前后不能丢失未改动内容、不能出现同一内容的重复召回。

文档管理后台提供这一能力：运营用 API Key 登录后，勾选文档批量上线/下线，一次提交完成切换。上传写入采用自包含去重，确保下线老文档后未改动内容仍可检索。评测可指定文档集合，支持上线前对草稿批次预演。

模型保持最简：不做版本、整体替换、检索折叠等抽象，靠"单次提交的批量状态变更"避免新老同时在线的重复召回窗口。

### 3.2 关键特性

- **勾选式批量上下线**：列表勾选 + 一次提交，上线与下线在同一请求内生效。
- **未改动内容不丢失**：上传时为新文档建立自包含检索条目，相同内容复用向量、不重复向量化。
- **API Key 登录**：复用现有 API Token，前端在浏览器持有 Key。
- **eval 指定集合**：评测可限定文档集合并支持草稿预演。

## 4. 业务规则与状态

### 4.1 业务规则

- **可见性即发布状态**：沿用文档生命周期，文档是否可被检索由 `published` 状态决定；批量上下线通过变更发布状态完成切换。
- **批量上下线为单次提交**：用户勾选的"上线集合"与"下线集合"在同一请求内一起生效，提交前检索见旧、提交后见新，避免新老同时在线导致的同一内容重复召回。
- **未改动内容不丢失**：上传新文档时为每个文档建立自包含检索条目，即使内容与线上完全相同；相同内容仅复用已有向量、不产生额外向量化。这样下线老文档后，未改动内容仍挂在新文档下、可被检索。
- **单文档契约不变**：单文档发布、取消发布、删除、上传的行为与现有契约一致；批量、登录、eval 为叠加层。
- **eval 集合语义**：评测指定文档集合时，检索限定到该集合且不受"仅已发布可见"限制（支持上线前预演草稿批次）；不指定集合时维持线上行为（只命中已发布文档）。
- **鉴权复用**：管理后台与文档管理接口复用现有 API Token；前端在浏览器持有 Key 并随请求携带。

### 4.2 关键状态与异常

- **批量请求含无效项**：批量上线/下线请求中混入不存在、处理中、失败或当前状态不允许该操作的文档时，逐条返回每项是否生效及未生效原因；已生效项正常生效，不整体回滚（就绪与冲突语义与单文档一致）。
- **API Key 失效**：管理后台请求被拒绝并引导回登录页重新输入 Key。
- **分别操作（已知限制）**：单文档端点仍可分别调用，若用户先上线新再下线老，存在短暂新老同时在线的重复召回窗口；推荐使用批量单次提交规避。

## 5. 功能需求

### 5.1 核心需求

1. **文档管理后台**
   - 提供 API Key 登录页；登录后进入受保护的文档管理页。
   - 文档列表展示文件名、状态、行数、上传时间、错误信息，支持按状态筛选。
   - 支持文件上传、删除。
   - 支持行级勾选 + 批量上线/下线（一次提交）。

2. **批量上下线（单次提交）**
   - 一次请求内完成"上线一组 + 下线一组"的状态变更。
   - 就绪与冲突语义与单文档发布/取消发布一致；无效项逐条返回生效情况与原因，不整体回滚。

3. **写入去重自包含**
   - 上传新文档时始终为该文档建立独立检索条目；相同内容复用已有向量、不重复向量化。

4. **API Key 登录**
   - 用系统现有 API Key 校验登录；前端持有 Key 并随管理请求携带；Key 失效引导重新登录。

5. **eval 指定文档集合**
   - 评测可指定一组文档；指定时检索限定到该集合且不受"仅已发布可见"限制；不指定时维持线上行为。

### 5.2 验收目标

- 管理后台可勾选"上线新批次 + 下线老批次"一次提交；提交后检索只命中新内容、不命中老内容、无空窗、无同一内容重复召回。
- 新批次含与老批次完全相同的内容时，切换后这些内容在新批次下仍可检索、不丢失。
- 批量请求混入不存在或状态不允许的文档时，逐条返回生效情况与原因，已生效项不回滚。
- 用有效 API Key 可登录管理后台；无效 Key 被拒；Key 失效后引导重新登录。
- eval 指定文档集合时，检索结果只来自该集合且可评测草稿批次；不指定时维持线上已发布行为。
- 单文档发布、取消发布、删除、上传行为与启用本能力前一致。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：批量上下线（单次提交，上线集合 + 下线集合）、API Key 登录校验、eval 指定文档集合评测；均受 API Token 鉴权保护，与现有文档管理接口一致。
- **访问控制**：复用现有 API Token；前端在浏览器持有 Key 并随请求携带。不引入 session、用户表或多角色账户体系。
- **数据边界**：单一知识库；无多租户、无 realm 分片。
- **就绪与冲突语义**：批量/登录/eval 操作的就绪与状态冲突语义与单文档发布/取消发布一致；批量含无效项时逐条返回生效情况与原因，不整体回滚。
- **兼容性**：单文档发布、取消发布、删除、上传的请求/响应契约保持不变；批量、登录、eval 为叠加层。
- **接口明细**：端点、请求/响应结构、状态码契约由 `/t-design` 承接，不在本 PRD 展开。

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：登录页（输入 API Key）+ 文档管理后台（登录后可访问，未登录重定向到登录页）。
- **关键交互**：
  - 文档列表：展示文件名、状态、行数、上传时间、错误信息；按状态筛选。
  - 上传：文件选择/拖拽上传。
  - 批量操作：行级勾选 → 批量上线/下线 → 单次提交。
  - 删除：单条或批量删除。
- **状态反馈**：上传中/处理中/草稿/已发布/失败 各状态可见；批量操作逐条反馈生效情况与未生效原因。
- **权限可见性**：管理后台全程要求有效 API Key；Key 失效时操作被拒并引导重新登录。

## 8. 已确认决策

- **采用最简勾选式模型**：管理后台勾选 + 单次提交批量上下线；不做版本分组、整体替换、蓝绿切换、检索折叠等抽象。
- **写入去重为自包含**：上传时始终为新文档建立独立检索条目、相同内容复用向量不重复向量化；下线老文档后未改动内容不丢失。
- **批量上下线为单次提交**：上线与下线集合在同一请求内生效，避免新老同时在线的重复召回窗口，故不需要检索层折叠。
- **鉴权复用 API Token**：前端在浏览器持有 Key；不引入 session、用户表或多角色账户体系。
- **eval 增加文档集合维度**：指定集合时检索限定到该集合并支持草稿预演；不指定时维持线上行为。
- **不提供**：版本/整体替换/折叠、多用户账户体系、旧版本自动清理（均列为后续）。
