## 2. 范围界定

### 2.1 包含功能

- **统一检索编排**：「查询改写 → 混合检索 → 内容去重 → 可选 rerank」是产品内统一的检索编排能力；主站搜索、聊天问答、MCP 工具、内部评测（eval）共用同一编排与同一排序口径。
- **标题命中加权**：标题命中查询关键词的知识片段，在最终排序中获得有限的权重提升；在统一编排内生效，所有检索入口一致。
- **公开频道级搜索能力**：面向前端与第三方的公开搜索能力——按频道直接检索已发布文档的知识片段，返回带来源信息的排序结果列表，不经 LLM 生成回答；访问与返回语义与既有 MCP 检索工具同口径。
- **主站搜索框**：主站频道页提供搜索框，回车或点击搜索按钮触发检索，结果以下拉列表展示（标题、内容摘要、来源链接），点击可打开来源页面。
- **结果关键词高亮**（US-CORE-043）：结果标题与摘要中命中检索词的片段以高亮样式标出；切词与匹配在前端完成（词级、大小写不敏感、单字与纯标点不高亮），高亮跟随产生本批结果的检索词；`/api/search` 返回结构不变。
- **结果键盘操作**（US-CORE-043）：方向键在输入框、「用 AI 回答」入口与带链接的结果条目之间移动焦点，回车执行当前条目的动作（打开来源或发起 AI 问答）；无链接条目不可聚焦；输入法组合输入时方向键不被拦截。
- **「用 AI 回答」入口**（US-CORE-044）：有结果时在结果列表上方固定展示，点击或聚焦后回车将当前检索词交给聊天问答——打开聊天窗口并把检索词作为一轮提问自动发出（复用公开聊天 SSE 链路与当前会话语义）；仅显式触发才产生 LLM 生成成本，零命中与检索失败时不出现该入口。

### 2.2 不包含功能 (Out of Scope)

- Widget 搜索框：可嵌入聊天组件不加载搜索入口；需要时另行立项。
- 输入即时（防抖）搜索：仅回车/按钮触发，输入过程不产生检索请求。
- 访问限流与配额：属全局能力，另行立项；公开搜索与公开聊天、MCP 入口同口径暴露（沿用 `integration/mcp-server.md` 已发布基线）。
- FTS 列权重与数据库结构改造：不改造全文索引结构、无数据库迁移。
- 后端返回结构变更（如接口返回高亮偏移）：高亮为前端呈现增强，接口返回结构不变（原「搜索结果关键词高亮」排除项按 §8 于 2026-11-09 重开为前端呈现层能力）。
- 结果分页/翻页与游标：单次返回上限内结果，上限与 MCP 检索工具同口径。
- 搜索历史、热门搜索、拼写纠错等搜索运营功能。
- 管理端鉴权口径的搜索接口：搜索为公开口径，需要管理端口径时按 §8 重开条件处理。

### 2.3 依赖项

- **检索行为基线**：查询改写与降级（`docs/prd/chat/query-rewrite.md`）、关键词与混合检索（`docs/prd/document/keyword-search-support.md`）、rerank 精排与降级（`docs/prd/core/rerank-investigation.md`）、上下文组装与引用（`docs/prd/chat/chat-context-prompt-assembly.md`）。
- **频道规则**：`channelId` 校验、频道数据隔离与频道标识格式规则（`docs/prd/integration/support-multiple-website.md`）；公开访问原则与检索工具口径先例（`docs/prd/integration/mcp-server.md`）。
- **发布状态过滤**：仅已发布文档可被检索（`docs/prd/document/document-lifecycle.md`）。

## 3. 需求概述

### 3.1 功能描述

RWiki 的检索编排（改写 → 混合检索 → 去重 → rerank）是统一能力，主站搜索、聊天问答、MCP 工具、内部评测（eval）四类入口共用同一编排与同一排序口径。专门搜索在此之上提供三项能力：公开的频道级搜索能力，让前端与第三方无需接入聊天或 MCP 即可直接检索知识片段，也不为 LLM 生成付费；标题命中加权，让最直接匹配查询意图的内容在所有入口优先呈现；主站频道页搜索框，让访问者以「搜索」而非「对话」的方式使用知识库。标题加权与统一排序口径在所有检索入口一致呈现。搜索框在直接检索之上还承载结果呈现增强（US-CORE-043 高亮与键盘操作）与向 AI 问答的一键升级（US-CORE-044），前者不动接口，后者复用公开聊天链路。

### 3.2 关键特性

- **专门搜索出口**：不经 LLM 生成的直接检索能力，延迟与成本显著低于问答。
- **编排统一**：所有检索入口共用同一编排与排序口径，同一查询同源结果。
- **标题加权**：融合与精排之后的有限权重提升，默认启用、全入口一致、不颠覆内容高度相关的头部排序。
- **主站搜索框**：回车/按钮触发、下拉展示、点击直达来源，公开访问无需凭据。
- **结果呈现增强**：命中词高亮与方向键/回车操作让结果可扫读、可键盘直达（US-CORE-043），纯前端、零额外请求。
- **向 AI 问答升级**：「用 AI 回答」把当前检索词一键交给公开聊天链路（US-CORE-044），仅显式触发产生 LLM 成本。

## 4. 业务规则与状态

### 4.1 业务规则

- **访问规则**：公开搜索为公开能力，不要求任何凭据，不受 API Token 与来源 IP 白名单保护，携带凭据的请求照常处理；与公开聊天、MCP 入口同一暴露级别，仅消费各频道已发布内容。
- **频道规则**：检索必须指定有效频道标识，缺失、未定义均拒绝并返回明确提示，不回退到任何默认频道；检索仅发生在指定频道的已发布文档集合内，单次请求不可见、不可枚举其他频道内容。
- **结果口径**：频道无已发布文档与检索零命中统一返回空结果，不视为错误；「查询无相关内容」以检索零命中（混合检索未召回任何片段）为判定口径，与聊天/MCP 行为一致，不引入相关性阈值或低分过滤；结果按相关性排序——page 之间按页内最高片段得分稳定降序，同一 page 内片段按章节顺序稳定排列；单次返回数量上限与 MCP 检索工具同口径。
- **返回信息口径**：每条结果包含标题、章节、内容、来源链接、语言与相关性得分，与 MCP 检索工具的返回口径一致；得分含义为越高越相关，不同链路的得分不可相互比较。
- **标题加权规则**：加权作用于融合与精排（若启用）之后的最终排序阶段；命中判定为查询分词后的任一关键词出现在片段标题中（大小写不敏感）；权重提升为固定值，默认启用，不提供运行时配置；加权是有限提升而非绝对置顶，不颠覆内容高度相关结果的头部排序；标题未命中的片段保持既有相对顺序。
- **全入口一致**：标题加权与最终排序在统一检索编排内生效，主站搜索、聊天问答、MCP 工具、内部评测的检索排序同步变化，同一查询在各入口呈现一致口径。
- **降级规则**：沿用既有基线——查询改写失败降级为原始查询、关键词检索失败降级为纯向量检索、rerank 失败降级为融合结果；公开搜索同样适用，降级不中断请求、使用者不感知。
- **前端触发规则**：仅在回车或点击搜索按钮时发起检索，输入过程不触发检索请求。
- **高亮规则**（US-CORE-043）：高亮词表由「产生本批结果的检索词」切词得出（词级、大小写不敏感），单字与纯标点词不高亮；只作用于标题与摘要，来源链接行不高亮；命中判定是词级字面匹配，不引入同义改写。提交新检索后高亮随新结果整体替换。
- **键盘操作规则**（US-CORE-043）：方向键移动真实焦点——输入框 →「用 AI 回答」入口 → 带链接的结果条目（无链接条目不可聚焦、被跳过），焦点条目上的回车执行其原生动作（新标签页打开来源 / 发起 AI 问答），焦点在输入框时回车维持「重新检索」既有语义；输入法组合输入时方向键与回车均不被拦截；焦点位于条目时 Esc 收起下拉并回到输入框。
- **「用 AI 回答」规则**（US-CORE-044）：交出的是产生本批结果的检索词（非当前输入框草稿）；点击或回车触发一次后下拉收起、输入框关键词保留；交给 AI 等价于在聊天框输入并发送——复用当前会话与公开聊天 SSE 链路，有回答在途时按聊天既有语义中断；检索零命中或失败时不渲染该入口。

### 4.2 关键状态与异常

- **检索进行中**：主站搜索区域展示加载状态，结果返回后替换为本次结果列表。
- **有结果**：下拉列表展示按相关性排序的片段；命中检索词的标题/摘要片段高亮；「用 AI 回答」入口固定于结果列表上方。
- **无相关内容（零命中）/ 频道无已发布文档**：返回空结果，主站展示明确的无结果提示，不报错；不展示「用 AI 回答」入口。
- **频道无效**：请求被拒绝并返回明确提示，不返回任何知识库内容。
- **结果缺少来源链接**：条目正常展示标题与摘要，点击不发生跳转。
- **检索依赖降级**（改写、关键词检索或 rerank 失败）：请求仍正常返回结果或空结果，使用者不感知内部降级。
- **焦点在结果条目上**：焦点条目有可见的焦点样式，回车执行其动作；Esc 收起下拉，焦点回到输入框。

## 5. 功能需求

### 5.1 核心需求

1. **统一检索编排**
   - 「查询改写 → 混合检索 → 内容去重 → 可选 rerank」的编排是主站搜索、聊天问答、MCP 工具与内部评测共用的唯一检索编排入口。
   - 编排内既有降级与指标口径不变；最终排序统一为 page 级相关性排序（§4.1），全入口一致。

2. **标题命中加权**
   - 在统一编排的最终排序阶段，对标题命中查询关键词的片段叠加固定权重提升并稳定重排。
   - 命中判定复用与检索一致的分词口径；权重量级保守校准，不颠覆内容高度相关结果的头部排序。

3. **公开频道级搜索能力**
   - 支持按频道检索已发布文档的知识片段，返回带来源信息的排序结果列表，不经 LLM 生成。
   - 访问、频道校验、空结果与返回口径遵循 4.1 规则，语义与 MCP 检索工具同口径。
   - 纳入既有接口文档与前端类型生成链路，供前端与第三方消费。

4. **主站搜索框**
   - 频道页（频道就绪状态）提供搜索框入口；频道未知或配置不可用时页面不展示搜索框、不发起任何请求。
   - 回车或点击搜索按钮触发检索；结果以下拉列表展示标题、内容摘要与来源链接。
   - 提供检索中、无结果、频道无效等状态反馈；点击带来源链接的结果打开来源页面。

5. **结果呈现增强与 AI 入口**（US-CORE-043/044）
   - 结果标题与摘要按产生本批结果的检索词高亮：词级、大小写不敏感，单字与纯标点词不高亮；来源链接行不高亮；接口返回结构不变。
   - 方向键在输入框、「用 AI 回答」入口、带链接结果条目之间移动焦点；焦点条目上的回车执行其动作；无链接条目被跳过；输入法组合输入时方向键与回车不被拦截。
   - 「用 AI 回答」入口仅在有结果时展示于结果列表上方：交出产生本批结果的检索词，打开聊天窗口并自动发送（复用公开聊天 SSE 链路与当前会话语义）；零命中与检索失败时不出现。

### 5.2 验收目标

- 不携带任何凭据按频道检索，返回该频道已发布文档的排序片段，返回口径与 MCP 检索工具一致；携带凭据得到相同结果。
- 频道标识缺失或未定义的检索请求被拒绝并返回明确提示；频道无已发布文档或检索零命中时返回空结果且不视为错误；结果仅来自指定频道。
- 同一查询在聊天问答、MCP 检索工具、主站搜索呈现一致的排序结果。
- 构造「标题命中与未命中且内容相关性接近」的对照查询：标题命中片段的排序提前；标题未命中的片段集合保持既有相对顺序；内容高度相关但标题未命中的片段仍可排在标题命中但内容无关的片段之前。
- 检索质量不劣化：以评测基线对比，标题加权引入的排序变化为改善而非劣化。
- 主站搜索框回车与搜索按钮均可触发检索；输入过程不产生检索请求；检索中展示加载状态；无相关内容展示无结果提示；点击带来源链接的结果打开来源页面，无链接条目不跳转。
- 结果标题与摘要中命中检索词的片段被高亮；未命中文本与来源链接行不高亮；编辑输入框但未重新提交时高亮与结果保持不变。
- 方向键可从输入框依次走到「用 AI 回答」入口与带链接条目（无链接条目被跳过，首项之前回到输入框）；条目上回车打开其来源页面且不触发新检索；输入法组合输入时方向键不被拦截。
- 点击「用 AI 回答」（或聚焦后回车）：聊天窗口打开，检索词作为用户消息出现在会话中并发往本频道；搜索下拉收起，输入框关键词保留；零命中与检索失败时不出现该入口。
- 聊天问答与 MCP 工具的既有请求/响应行为保持不变（标题加权与检索排序统一带来的排序变化除外）；Widget、文档管理等既有功能不受影响。
- 改写或检索依赖失败时，搜索请求仍返回结果或明确空结果，使用者不感知内部降级。

## 6. API 相关约束

**适用性**: 适用

- **能力范围**：提供公开只读搜索能力——频道级检索已发布文档的知识片段；不暴露文档管理、反馈或其他管理类操作；纳入既有接口文档体系。
- **访问控制原则**：公开能力，不要求凭据，不受 API Token 与 IP 白名单保护，与公开聊天、MCP 入口同一暴露级别；管理类接口的鉴权边界不变。
- **数据边界**：频道标识是检索的数据隔离边界，语义与公开聊天、MCP 工具一致；仅已发布文档可被检索。
- **兼容性要求**：聊天、MCP、内部评测入口共用统一检索编排（标题加权带来的排序变化为预期差异并全入口一致）；搜索能力经既有接口文档与前端类型生成链路交付。具体端点、参数与响应结构由接口文档承载。US-CORE-043/044 为前端呈现与交互增强，`/api/search` 请求与响应结构不变；「用 AI 回答」复用既有 `/api/chat`，不新增接口。

## 7. 前端/交互约束

**适用性**: 适用

- **页面入口**：主站频道页提供搜索框入口；可嵌入 Widget 不加载搜索框；频道未知或配置不可用时不展示搜索框。
- **文档站入口（US-CORE-045，2026-11-09）**：docs-web 全站 Ctrl+K 搜索弹窗接入 `POST /api/search`（替换原静态客户端索引）：仅输入不检索、输入框回车触发、结果按 page 分组（标题 + 章节摘要）、点击/回车在站内打开来源页、可选「用 AI 回答」入口把检索词交给页面上的 rwiki 聊天 widget（依赖新版 widget 的 `ask()`；旧版 widget 不渲染该入口）；英文站检索 `help_center`、中文站检索 `help_center_zh`，频道按站点语言映射且与聊天 widget 一致。结果条目无来源链接（如 OpenAPI 分块）不展示。
- **关键交互**：输入关键词后回车或点击搜索按钮触发检索；结果以下拉列表展示标题、内容摘要与来源链接；点击带来源链接的结果打开来源页面；输入过程不触发检索请求。
- **结果呈现**：标题与摘要中命中检索词的片段高亮（词级、大小写不敏感；来源链接行不高亮）；「用 AI 回答」入口固定于结果列表上方、不随列表滚动。
- **键盘操作**：方向键在输入框、AI 入口、带链接条目之间移动焦点（无链接条目跳过）；焦点条目回车执行其动作，输入框回车重新检索；输入法组合输入时方向键与回车不被拦截。
- **AI 升级**：点击「用 AI 回答」打开聊天窗口并把产生本批结果的检索词自动发送（复用公开聊天链路）；交出后下拉收起、关键词保留；零命中与失败态不出现入口。
- **状态反馈**：检索中展示加载状态；无相关内容展示明确无结果提示；频道无效等业务异常以明确提示呈现，不展示空白或未处理错误。
- **权限可见性**：搜索为公开能力，访问者无需登录或持有凭据。

## 8. 已确认决策

- **统一编排 + 公开频道级搜索**：检索编排为产品内统一能力，聊天问答、MCP 工具、内部评测与主站搜索共用；搜索以公开的频道级能力交付，语义对标 MCP 检索工具。需要改为管理端鉴权口径或关闭公开暴露时重开决策。
- **标题权重方式**：在 RRF 融合及 rerank 之后的最终排序阶段，对标题命中查询关键词的片段叠加固定权重重排；不做全文索引列权重改造。出现词频级精确权重需求或加权效果不达标时重开决策。
- **前端搜索范围与形态**：仅主站频道页提供搜索框，回车/按钮触发、下拉展示；Widget 不含搜索框；不做输入即时（防抖）搜索。需要把搜索框引入 Widget、改为输入即时搜索或调整触发方式时重开决策。2026-11-09 重开范围（原「搜索结果关键词高亮」排除项与键盘导航排除）：结果高亮与键盘操作纳入主站搜索框（纯前端、不改触发方式、不新增请求）；「用 AI 回答」入口复用公开聊天链路，仅显式触发产生 LLM 成本。后端返回结构变更（如接口返回高亮偏移）、搜索运营功能（历史/热门/纠错）仍按排除项处理。2026-11-09 再次重开（文档站接入，US-CORE-045）：docs-web 的 Ctrl+K 搜索由 fumadocs 静态客户端索引改为 rwiki `/api/search` 语义检索，回车触发、请求体与主站同口径（query + channelId，不带 topK）；交互沿用文档弹窗既有键盘/高亮能力，纯前端实现；静态索引路由、orama 依赖与部署层 carve-out 一并移除。API 参考页（OpenAPI 分块无来源链接）无法从文档站搜索直达，维持排除。
- **空结果判定口径**：「查询无相关内容返回空结果」以检索零命中为判定口径，与聊天/MCP 行为一致；不引入相关性阈值或低分过滤。需要为搜索或全部检索入口增加低分过滤/相关性阈值时重开决策。
