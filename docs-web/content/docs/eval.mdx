RWiki does not ship a local Python eval runner. Instead, the backend exposes a
stable eval endpoint that runs the full RAG pipeline and returns payloads shaped
for open-source evaluators such as Ragas, DeepEval, and RAGChecker.

Use eval when you change retrieval, rerank, prompts, or model config and need to
compare answer quality with a fixed golden dataset.

## Eval API

`POST /api/eval/query` runs query rewrite, hybrid retrieval, optional rerank, and
non-streaming answer generation. It requires the same Bearer token used by
document management APIs.

### Request

```json
{
  "queryId": "q001",
  "query": "How to upload documents?",
  "topK": 5,
  "referenceAnswer": "Upload documents with POST /api/documents/upload.",
  "sessionId": "optional-session-id"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `queryId` | string | No | Stable eval case ID, forwarded to evaluator payloads. |
| `query` | string | Yes | User query text. Empty or whitespace returns 400. |
| `topK` | number | No | Number of retrieved contexts to return. Defaults to `[retrieval].max_context_chunks`. |
| `referenceAnswer` | string | No | Golden answer for correctness metrics. |
| `sessionId` | string | No | Reuse an existing chat session for rewrite context. |

## Recommended Tools

Ragas is the best default for dataset-style RAG regression. Use
`evaluation.ragas` for faithfulness, answer relevancy, context precision/recall,
and answer correctness.

DeepEval fits test-driven CI. Use `evaluation.deepeval` to build
`LLMTestCase(input, actual_output, expected_output, retrieval_context)` and run
metrics such as `FaithfulnessMetric`, `AnswerRelevancyMetric`,
`ContextualPrecisionMetric`, and custom `GEval` rules.

RAGChecker is useful when you need deeper diagnosis. Pass `referenceAnswer` and
use `evaluation.ragchecker` for claim-level metrics such as overall
precision/recall, context utilization, hallucination, and faithfulness.

Phoenix is useful for tracing and dashboards. Keep the raw response fields
(`query`, `searchResults`, `answer`, `timingMs`) as span attributes, then log
evaluator scores back as annotations.

## Golden Dataset

Keep golden data outside this repository or in your test infrastructure. A
minimal JSONL case should include:

```json
{"queryId":"q001","query":"How to upload documents?","referenceAnswer":"Upload documents with POST /api/documents/upload.","expectedDocIds":["doc-001"]}
```

For each case, call `/api/eval/query` with `queryId`, `query`, `topK`, and
`referenceAnswer`. The external evaluator can compute retrieval metrics from
`searchResults[].documentId` and answer metrics from `evaluation`.

## Quick Test

```bash
curl -X POST http://localhost:8080/api/eval/query \
  -H "Authorization: Bearer dev-test" \
  -H "Content-Type: application/json" \
  -d '{"queryId":"q001","query":"What file formats does RWiki support?","topK":5}'
```

## Error Responses

| Status | When |
|--------|------|
| 400 | `query` is empty or whitespace |
| 401 | Missing or invalid Bearer token |
| 503 | Knowledge base has no indexed data |
