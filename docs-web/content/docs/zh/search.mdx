每个频道页（`/c/{channelId}`）在聊天入口上方有一个搜索框。按回车或点击搜索按钮触发检索；单纯输入不产生任何请求，逛页面不花检索成本。搜索只覆盖该频道的已发布文档，无需任何凭据。

结果以搜索框下方的下拉列表呈现。每条展示页面标题、两行摘要和来源链接，链接在新标签页打开。来源链接缺失的条目正常展示但不可点击。排序是 page 级相关度：page 之间按页内最高片段得分排列，同一 page 内保持文档顺序。聊天引用和 MCP `rwiki_search` 用同一套排序，同一个查询在所有入口顺序一致。

## 高亮与键盘

检索词命中标题或摘要的部分会在结果里标出。标亮按词匹配、大小写不敏感；单字和纯标点不高亮。高亮跟随产生当前结果的检索词，编辑输入框但不重新提交时不会有任何变化。

方向键在下拉里移动焦点：从输入框到「用 AI 回答」入口，再到带链接的结果条目。无来源链接的条目会被跳过，因为它们没有可执行的动作。焦点条目上按回车等同于点击，打开来源页，且不触发新的检索。输入框内按回车是重新检索。Esc 收起下拉并把焦点还给输入框；之后再按 ↓ 会重新展开结果，不发请求。中文输入法组合输入期间，方向键和回车都留给输入法。

## 用 AI 回答

搜索有结果时，列表上方有一行入口把查询交给聊天：点击（或聚焦后按回车），聊天窗口打开，检索词已经作为一轮提问发出，回答按正常聊天链路流式返回，并延续当前会话。下拉随之收起，关键词留在搜索框里便于继续调整。

交出去的是产生当前结果的检索词，不是输入框里的草稿。入口只在有结果时出现：零命中或检索失败时，聊天走同一条检索链路同样什么都找不到，与其多付一次 LLM 调用换一句「不知道」，不如不展示。

## 搜索 API

同一个搜索也以公开接口提供，不经 LLM 生成，无需凭据：

```bash
curl -X POST http://localhost:8080/api/search \
  -H "Content-Type: application/json" \
  -d '{"query":"如何上传文档","channelId":"help_center"}'
```

响应的 `results[]` 里每个条目含 `title`、`section`、`content`、`link`、`locale`、`score`、`documentId`。零命中返回空列表，不是错误。可选参数 `topK`（1 到 20）限制返回条数；不传时用检索配置的缺省值，与 MCP 工具同口径。完整 schema 见 [`search_chunks` OpenAPI 页](/zh/docs/openapi/search_chunks)。

检索走与聊天、MCP 相同的编排：查询改写、关键词加向量混合检索、去重、可选 rerank，最后 page 级排序。同一个查询、同一个频道，页面搜索框和 `rwiki_search` 拿到同一份结果。

Widget 构建不包含搜索框，搜索是主站功能。
