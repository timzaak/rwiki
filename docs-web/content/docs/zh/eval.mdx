RWiki 不再内置本地 Python eval runner。后端只提供稳定的 eval 接口：跑完整
RAG 管线，并返回适配 Ragas、DeepEval、RAGChecker 等开源评估框架的 payload。

当你修改检索、rerank、prompt 或模型配置时，用固定 golden dataset 调用这个接口，
再用外部评估框架比较回答质量。

## Eval API

`POST /api/eval/query` 会执行查询改写、混合检索、可选 rerank 和非流式回答生成。
接口需要 Bearer token，和文档管理 API 使用同一个 `[api] token`。

### 请求

```json
{
  "queryId": "q001",
  "query": "如何上传文档？",
  "topK": 5,
  "referenceAnswer": "通过 POST /api/documents/upload 上传文档。",
  "sessionId": "optional-session-id"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `queryId` | string | 否 | 稳定的评估用例 ID，会透传到评估 payload。 |
| `query` | string | 是 | 用户查询。为空或纯空格返回 400。 |
| `topK` | number | 否 | 返回的检索上下文数量，默认使用 `[retrieval].max_context_chunks`。 |
| `referenceAnswer` | string | 否 | 用于 correctness 指标的标准答案。 |
| `sessionId` | string | 否 | 复用已有聊天会话，让查询改写利用对话历史。 |
| `documentIds` | string[] | 否 | 限定到一组文档评测。检索只命中该集合，并放开发布限制（可评测 `draft` 草稿批次）。缺省或空数组维持线上行为（仅 `published`）。 |

## 评测指定文档集合

传入 `documentIds` 把检索限定到一组文档，并放开发布限制——可以评测还在 `draft` 的草稿批次，在上线前预演质量（见[文档管理后台](/docs/zh/admin)）。不传或传空数组则维持线上行为，只命中已发布文档。

```bash
curl -X POST http://localhost:8080/api/eval/query \
  -H "Authorization: Bearer dev-test" \
  -H "Content-Type: application/json" \
  -d '{"query":"如何上传文档？","documentIds":["0196a1b2-3c4d-7e5f-8a9b-0c1d2e3f4a5b"],"topK":5}'
```

## 推荐开源方案

Ragas 适合默认的 RAG 回归评估。使用 `evaluation.ragas` 计算 faithfulness、
answer relevancy、context precision/recall 和 answer correctness。

DeepEval 更适合测试驱动和 CI。使用 `evaluation.deepeval` 构造
`LLMTestCase(input, actual_output, expected_output, retrieval_context)`，再运行
`FaithfulnessMetric`、`AnswerRelevancyMetric`、`ContextualPrecisionMetric` 或自定义
`GEval`。

RAGChecker 适合做更细的诊断。调用接口时传入 `referenceAnswer`，再使用
`evaluation.ragchecker` 计算 claim 级别的 overall precision/recall、
context utilization、hallucination 和 faithfulness。

Phoenix 适合做 trace 和看板。把原始响应字段（`query`、`searchResults`、`answer`、
`timingMs`）记录为 span 属性，再把评估分数作为 annotation 写回。

## Golden Dataset

golden 数据建议放在仓库外或测试基础设施中。最小 JSONL 用例：

```json
{"queryId":"q001","query":"如何上传文档？","referenceAnswer":"通过 POST /api/documents/upload 上传文档。","expectedDocIds":["doc-001"]}
```

每条用例调用 `/api/eval/query` 时传入 `queryId`、`query`、`topK` 和
`referenceAnswer`。外部评估工具可以用 `searchResults[].documentId` 计算检索指标，
用 `evaluation` 计算最终答案指标。

## 快速测试

```bash
curl -X POST http://localhost:8080/api/eval/query \
  -H "Authorization: Bearer dev-test" \
  -H "Content-Type: application/json" \
  -d '{"queryId":"q001","query":"RWiki 支持哪些文件格式？","topK":5}'
```

## 错误响应

| 状态码 | 触发条件 |
|--------|----------|
| 400 | `query` 为空或纯空格 |
| 401 | 缺少或无效的 Bearer token |
| 503 | 知识库没有索引数据 |
