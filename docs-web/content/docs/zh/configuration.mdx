配置文件位于 `backend/config/config.toml`，TOML 格式。初次使用时从 `backend/config/config.example.toml` 复制：

```bash
cp backend/config/config.example.toml backend/config/config.toml
```

启动时 `AppConfig::load()` 读取配置文件，之后环境变量覆盖对应字段。优先级：**环境变量 > 配置文件**。

配置文件路径默认为 `config/config.toml`（相对于工作目录），可通过环境变量 `APP_CONFIG` 指定其他路径。

## 环境变量

| 环境变量 | 覆盖字段 | 说明 |
|---|---|---|
| `APP_CONFIG` | 配置文件路径 | 默认 `config/config.toml` |
| `OPENAI_API_KEY` | `embedding.api_key` | Embedding API Key |
| `API_TOKEN` | `api.token` | 文档管理接口的 Bearer Token |
| `API_ALLOWED_IP_RANGES` | `api.allowed_ip_ranges` | 逗号分隔的 CIDR 列表，限制哪些客户端 IP 能访问受保护接口。覆盖配置文件中的值。为空时不限制来源 IP |
| `CORS_ALLOWED_ORIGINS` | `server.allowed_origins` | 聊天 widget（嵌入第三方网站）的来源允许列表，逗号分隔。为空时允许所有来源（`*`，默认）。设置具体来源以限制哪些网站能调用 `/api/chat` |
| `OTEL_LICENSE_KEY` | `otel.license_key` | OTLP 鉴权 Token |
| `RERANK_API_KEY` | `rerank.api_key` | Rerank API Key |

## 服务器

`[server]` — 服务监听与运行时配置。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `bind_address` | string | 是 | — | 监听地址，如 `"0.0.0.0:8080"` |
| `log_level` | string | 是 | — | 日志级别：`trace`、`debug`、`info`、`warn`、`error` |
| `app_env` | string | 是 | — | 运行环境：`development`、`demo`、`test` |
| `static_dir` | string | 否 | — | 前端静态文件目录（生产模式使用），如 `"../frontend/dist"`。省略则不托管静态文件 |
| `allowed_origins` | string[] | 否 | `[]`（`*`） | 聊天 widget 的 CORS 来源白名单。widget 嵌入第三方网站时会跨域调用 `/api/chat`。为空=允许所有来源（`*`），开箱即用但任何网站都能调用你的接口；设置具体来源以收紧访问。详见 [Widget](#widget) |
| `enable_openapi` | bool | 是 | — | 是否启用 Swagger 文档（`/swagger`） |

## SQLite

`[sqlite]` — SQLite 数据库配置。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `path` | string | 是 | — | 数据库文件路径，如 `"data/rwiki.db"`。启动时自动创建父目录。 |

数据库启用 WAL 模式以支持并发读写。`vec_chunks` 表的向量列宽度由 embedding 模型维度决定。

## LLM

`[llm]` — LLM 对话模型配置。支持所有 OpenAI 兼容的 provider。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `api_key` | string | 是 | — | LLM API Key |
| `base_url` | string | 是 | — | API Base URL |
| `model` | string | 是 | — | 模型名称 |

不同 provider 的配置示例：

```toml
# OpenRouter（默认）
[llm]
api_key = "sk-or-..."
base_url = "https://openrouter.ai/api/v1"
model = "deepseek/deepseek-chat-v3-0324"

# OpenAI
[llm]
api_key = "sk-..."
base_url = "https://api.openai.com/v1"
model = "gpt-4o"

# 智谱 AI (GLM)
[llm]
api_key = "your-glm-api-key"
base_url = "https://open.bigmodel.cn/api/paas/v4"
model = "glm-4-flash"

# 阿里云百炼 (DashScope)
[llm]
api_key = "sk-..."  # 百炼控制台获取，sk- 开头
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
model = "qwen-plus"  # 也可 qwen-max / qwen-turbo / qwen-long
```

国内用户可仅用阿里云百炼一个 provider 和一个 API Key 同时驱动对话、向量化与精排（精排用 `provider = "dash_scope"`，见下方 Rerank 章节）。

## Embedding

`[embedding]` — 向量嵌入模型配置。所有字段均为可选，省略整个 `[embedding]` 段时使用 OpenAI 默认值。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `api_key` | string | 是* | — | API Key。优先使用 `OPENAI_API_KEY` 环境变量 |
| `base_url` | string | 否 | OpenAI 默认 | API Base URL，非 OpenAI provider 必须设置 |
| `model` | string | 否 | `"text-embedding-3-small"` | 模型名称 |
| `dimensions` | number | 否 | 模型默认 | 向量维度。BigModel 支持 256/512/1024/2048；Gemini 支持 768/1536/3072 |

**注意**：更换 embedding 模型后如果维度不同，需要删除旧数据库重建（服务启动时会自动校验维度一致性）。

配置示例：

```toml
# OpenAI（默认配置，只需设 api_key）
[embedding]
api_key = "sk-..."
# base_url、model、dimensions 均可省略

# 智谱 AI Embedding-3
[embedding]
api_key = "your-bigmodel-api-key"
base_url = "https://open.bigmodel.cn/api/paas/v4"
model = "embedding-3"
dimensions = 2048   # 可选：256 / 512 / 1024 / 2048

# 阿里云百炼 (DashScope)
[embedding]
api_key = "sk-..."  # 可与 [llm] 共用同一百炼 key
base_url = "https://dashscope.aliyuncs.com/compatible-mode/v1"
model = "text-embedding-v3"
dimensions = 1024   # 可选：512 / 768 / 1024

# Google Gemini（OpenAI 兼容层）
[embedding]
api_key = "your-gemini-api-key"  # 从 https://aistudio.google.com/apikey 获取
base_url = "https://generativelanguage.googleapis.com/v1beta/openai"
model = "gemini-embedding-001"
dimensions = 1536   # 必填：768 / 1536 / 3072
```

使用 Gemini 时有三个限制：

- `dimensions` 必须设置。`gemini-embedding-001` 默认输出 3072 维向量，而服务按这个配置值建 `vec_chunks` 向量表；省略时按 0 维建表，文档索引进不去。推荐 1536。
- 单条输入上限 2048 token。RWiki 按 1600 字符分块，英文文档不会碰到上限；中文长段落换算成 token 后可能超过 2048，Gemini 会以 HTTP 400 拒绝请求。遇到时把 `backend/core/src/infrastructure/text_chunker.rs` 里的 `DEFAULT_MAX_CHUNK_CHARS` 调小。
- `generativelanguage.googleapis.com` 在大陆无法直连，启动后端时需要设置代理环境变量，例如 `HTTPS_PROXY=http://127.0.0.1:7890`。

## API Token

`[api]` — 文档管理接口认证配置。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `token` | string | 是 | `""` | Bearer Token，用于文档上传/删除等管理接口。可通过 `API_TOKEN` 环境变量设置 |
| `allowed_ip_ranges` | string[] | 否 | `[]` | 受保护接口的 CIDR 允许列表。为空时不限制来源 IP（仅 Token 鉴权）；非空时，客户端 TCP peer IP 必须命中其中一个网段，否则返回 401。可通过 `API_ALLOWED_IP_RANGES` 环境变量设置（逗号分隔） |

**token 必须非空**，否则服务启动时 panic。建议通过环境变量设置：

```bash
export API_TOKEN="your-secret-token"
```

调用受保护接口时在请求头中携带：

```
Authorization: Bearer your-secret-token
```

这个 token 也是文档管理后台的登录密钥：前端用它在 `/admin` 登录（见[文档管理后台](/zh/docs/admin)）。

## Chat

`[chat]` — 对话行为配置。所有字段均有默认值，可省略整个 `[chat]` 段。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `system_prompt` | string | 否 | 内置默认提示词 | 系统提示词，定义助手角色与行为规则。多行文本用三引号 `"""..."""` |
| `sliding_window_size` | number | 否 | `6` | 滑动窗口保留最近 N 条消息用于上下文 |
| `compact_threshold` | number | 否 | `8` | 消息数超过此阈值时触发压缩检查 |
| `token_budget` | number | 否 | `8000` | 估算 token 数超过此阈值时触发压缩 |
| `content_language` | string | 否 | — | 知识库文档的主要语言（如 `"English"`、`"中文"`）。设置后，查询改写会将用户查询翻译为该语言，以提升跨语言检索命中率。省略时不做语言转换 |
| `suggested_questions` | map | 否 | — | 推荐问题，按语言标签分组。详见下方[推荐问题](#推荐问题)小节。 |
| `enable_post_answer_suggestions` | bool | 否 | `false` | 回答完成后生成后续推荐问题，经 SSE `suggestions` 事件下发。开启后每次回答追加一次非流式 LLM 调用（带超时与 token 预算）。默认关闭 |

### 滑动窗口与压缩机制

对话上下文管理分两层：

1. **滑动窗口**：每次请求只取最近 `sliding_window_size` 条消息发送给 LLM，丢弃更早的消息。
2. **压缩检查**：当消息总数超过 `compact_threshold` 条，或估算 token 数超过 `token_budget` 时，系统将历史消息压缩为摘要，释放 token 空间。

两个机制协同工作：滑动窗口控制单次请求的上下文长度，压缩机制防止历史无限增长。

RAG 检索结果由系统自动拼接到系统提示词之后，`system_prompt` 中不需要手动处理上下文占位符。

### 推荐问题

`suggested_questions` 配置聊天界面空状态下展示的推荐提问。按语言标签分组，前端根据用户语言自动匹配。

```toml
[chat.suggested_questions]
default = ["如何快速上手", "系统支持哪些文件格式"]
zh-CN = ["如何快速上手", "系统支持哪些文件格式", "如何提升回答准确性"]
en = ["How to get started", "What file formats are supported"]
```

匹配逻辑（后端 API 和前端一致）：

1. 精确匹配 locale key（不区分大小写）。`zh-CN` 匹配 `zh-CN`。
2. 最长前缀匹配。如果没配 `zh-TW` 但配了 `zh`，`zh-TW` 会命中 `zh`。
3. 都没匹配到时回退到 `default`。
4. 全都没命中则返回空数组。

后端通过 `GET /api/chat/suggestions?locale=zh-CN` 返回匹配结果，最多 10 条。前端会按 locale 缓存。

配置示例：

```toml
[chat]
system_prompt = """
你是一个技术文档助手，专注于帮助开发者理解项目文档。
规则：
1. 优先使用代码示例说明问题。
2. 引用时使用 [Source N] 格式标注来源编号，N 对应上下文中的 document index。
3. 如果多个来源提供相同信息，合并引用，如 [Source 1][Source 2]。
4. 如果来源之间信息冲突，说明冲突并分别引用。
"""
sliding_window_size = 10
compact_threshold = 12
token_budget = 12000
# content_language = "English"  # 知识库文档主要为英文时取消注释
```

## Retrieval

`[retrieval]` — RAG 检索数量配置。所有字段均有默认值，可省略整个 `[retrieval]` 段。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `search_top_k_per_query` | number | 否 | `5` | 每个改写查询变体召回的候选数量 |
| `max_context_chunks` | number | 否 | `12` | 最终送入 LLM 上下文的最大 chunk 数 |

`/api/eval/query` 可以通过请求里的 `topK` 覆盖单次评估的上下文数量。Chat 请求使用配置文件中的值。

```toml
[retrieval]
search_top_k_per_query = 5
max_context_chunks = 12
```

## OpenTelemetry

`[otel]` — OpenTelemetry OTLP tracing 和 metrics 导出配置。所有字段均有默认值，可省略整个 `[otel]` 段。`endpoint` 为空时不启用 OTLP tracing 和 metrics，本地开发零开销。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `endpoint` | string | 否 | `""` (空，即禁用) | OTLP gRPC endpoint（tracing 和 metrics 共用） |
| `license_key` | string | 否 | `""` | 鉴权 Token，可通过 `OTEL_LICENSE_KEY` 环境变量设置 |
| `service_name` | string | 否 | `"rwiki-backend"` | 在 trace 中显示的服务名称 |

配置示例（阿里云 ARMS）：

```toml
[otel]
endpoint = "https://tracing-analysis-dc-hz.aliyuncs.com:8090"
# license_key 推荐通过环境变量设置
service_name = "rwiki-backend"
```

## Rerank

`[rerank]` — Rerank 精排配置。**rerank 是否启用由是否存在 `[rerank]` 段决定：包含 `[rerank]` 段即启用，省略整个段落则禁用（零开销）。** 其余字段均有默认值。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `provider` | string | 否 | `"open_router"` | Rerank 服务提供商：`"open_router"`、`"big_model"` 或 `"dash_scope"` |
| `model` | string | 否 | Provider 默认值 | 模型名称。OpenRouter 默认 `cohere/rerank-v4-fast`，BigModel 默认 `rerank-pro`，DashScope 默认 `qwen3-rerank` |
| `base_url` | string | 否 | Provider 默认值 | API Base URL。不配置时各 provider 使用各自默认端点（DashScope 默认中国大陆 `https://dashscope.aliyuncs.com/compatible-api/v1/reranks`）。需要其他地域（如国际 host `dashscope-us.aliyuncs.com`）或自定义网关时，显式设置 `[rerank].base_url`。rerank 不从 `[llm].base_url` 推导地域。 |
| `top_n` | number | 否 | `20` | 送入 rerank 的最大候选数量 |
| `timeout_secs` | number | 否 | `3` | API 调用超时（秒） |
| `api_key` | string | 否 | — | 独立 API Key。不配置时复用 `[llm].api_key`。BigModel 必须配置独立 key。可通过 `RERANK_API_KEY` 环境变量设置 |

启用后（即配置中存在 `[rerank]` 段），rerank 失败（网络错误、超时、认证失败、响应解析错误）时自动降级到 RRF 融合结果，用户无感知，系统记录 warn 级别日志。

```toml
# OpenRouter Rerank（免费，推荐）
[rerank]
provider = "open_router"
model = "cohere/rerank-v4-fast"
top_n = 20
timeout_secs = 3
# api_key 不配置时复用 [llm].api_key
```

```toml
# 智谱 BigModel Rerank（国内低延迟）
[rerank]
provider = "big_model"
model = "rerank-pro"
top_n = 20
timeout_secs = 3
api_key = "your-bigmodel-api-key"
```

```toml
# 阿里云百炼 (DashScope) Rerank
[rerank]
provider = "dash_scope"
model = "qwen3-rerank"        # 推荐模型
top_n = 20
timeout_secs = 3
# api_key 不配置时复用 [llm].api_key
```

## Low Recall

`[low_recall]` — 低相关召回记录。和 rerank 一样，是否启用由是否存在 `[low_recall]` 段决定：包含 `[low_recall]` 段即启用，省略整个段落则禁用（零开销）。其余字段均有默认值。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `threshold` | number | 否 | `0.3` | 当一次 published 作用域对话查询的 top-1 相关度分数低于此值，或检索无任何结果时，记录该查询。分数取 rerank 的 `relevance_score`（0..1），建议同时启用 `[rerank]` 让阈值有意义 |

启用后，每次 `POST /api/chat` 请求只要 top-1 相关度低于 `threshold`——或完全没有召回结果——就会被写入记录表，写入是 fire-and-forget 的旁路任务：不影响回答内容和延迟，写入失败只记一条 warn 日志。记录保存原始问题、top-1 相关度、召回来源和时间，不含助手回答。记录永久保留（无 TTL）。运营在后台按分数区间和时间筛选查看（见[文档管理后台 → 低相关召回记录](/zh/docs/admin#低相关召回记录)）。只记录 published 作用域查询，scoped 评测查询不记录。

```toml
[low_recall]
threshold = 0.3   # 上线后从首批记录校准
```

默认 `0.3` 是粗糙的起点——rerank 分数分布要等真实流量才知道。复查首批记录后调整阈值，再决定是否值得扩展（聚类、看板、调优 UI 目前都不在本期范围内）。

## Widget

前端可通过 `npm run build:widget` 导出纯 JS 文件（`rwiki-chat.js`），嵌入任何网站作为聊天悬浮按钮。通过 `RWikiChat.init(config)` 初始化。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `apiUrl` | string | 是 | — | 后端地址，需以 `http://` 或 `https://` 开头 |
| `channelId` | string | 是 | — | 目标频道标识，必须为已配置的 `[channels.<channelId>]`。缺失时控制台输出 `channelId is required` 且不渲染。详见[多频道](/zh/docs/multi-channel)。 |
| `locale` | string | 否 | `navigator.language` | 界面语言。接受 BCP-47 标签，解析为受支持的语言（`en`、`zh-CN`）。任意中文变体（`zh`、`zh-Hans`、`zh-TW` 等）均解析为 `zh-CN`，其余回退到 `en`。 |
| `title` | string | 否 | 语言默认值 | 聊天窗口标题。不传时取语言默认值（`en`→`Rwiki Chat`，`zh-CN`→`Rwiki 助手`）。 |
| `primaryColor` | string | 否 | `"#3b82f6"` | 主题色，6 位 hex 色值 |
| `position` | string | 否 | `"right"` | 悬浮按钮位置：`left` 或 `right` |
| `welcomeMessage` | string | 否 | — | 欢迎语 |
| `messages` | object | 否 | — | 覆盖当前语言下的界面文案，可传任意子集：`titleDefault`、`inputPlaceholder`、`responseFailed`、`retry`、`a11yOpen`、`a11yClose`、`a11yClear`、`a11yLike`、`a11yDislike`、`errorBoundary`。 |
| `suggestedQuestions` | string[] 或 map | 否 | — | 推荐问题。数组用于单一语言，`Record<string, string[]>` 用于多语言分组（匹配逻辑与后端配置一致）。当目标频道已配置 `[channels.<channelId>.suggested_questions]` 时，本字段被忽略，以服务端为唯一来源（见[多频道](/zh/docs/multi-channel)）。 |

### HTML 集成

```html
<script src="rwiki-chat.js"></script>
<script>
  RWikiChat.init({
    apiUrl: 'https://your-rwiki-instance.com',
    channelId: 'help_center',
    locale: 'zh-CN',
    title: '智能助手',
    primaryColor: '#6366f1',
    position: 'right',
    welcomeMessage: '有什么可以帮你？',
    messages: { inputPlaceholder: '请输入问题…' },
    suggestedQuestions: {
      default: ['如何快速上手', '系统支持哪些文件格式'],
      en: ['How to get started', 'What file formats are supported'],
    },
  });
</script>
```

销毁实例：

```js
RWikiChat.destroy();
```

实时切换语言，无需重新初始化——Widget 原地重新渲染，当前对话保留：

```js
RWikiChat.setLocale('zh-CN');
```

`setLocale` 接受与 `locale` 配置相同的 BCP-47 标签，解析规则一致。必须在 `init` 之后调用；在 `init` 之前调用会打印错误且不生效。

Widget 通过 Shadow DOM 隔离样式，不会影响宿主页面 CSS。

### React 集成（docs-web 的方式）

React 应用中可以动态加载 widget 脚本。后端地址通过 `VITE_RWIKI_API_URL` 环境变量传入（构建时确定，定义在 `docs-web/vite.config.ts`）。把目标 `channelId` 和应用当前的 locale 传给组件，让 widget 跟随它：`init` 时传入初始值，locale 变化时调用 `setLocale`。

```tsx
// src/components/rwiki-chat-widget.tsx
import { useEffect, useRef } from 'react';

const apiUrl = import.meta.env.VITE_RWIKI_API_URL as string;

export default function RWikiChatWidget({ channelId, locale }: { channelId: string; locale: string }) {
  const firstRun = useRef(true);
  // 始终保存最新 locale：脚本异步加载时，onload 里的 init 读取此 ref，
  // 避免用到挂载时闭包捕获的过期 locale（修复 locale 在脚本加载期间变化的竞态）。
  const localeRef = useRef(locale);
  localeRef.current = locale;

  // 加载并初始化一次，传入初始 locale。
  useEffect(() => {
    const w = window as any;
    const initWidget = () => { w.RWikiChat?.init?.({ apiUrl, channelId, locale: localeRef.current }); };
    if (w.RWikiChat?.init) {
      initWidget();
    } else {
      const script = document.createElement('script');
      script.src = '/rwiki-chat.js';
      script.onload = initWidget;
      document.body.appendChild(script);
    }
    return () => { w.RWikiChat?.destroy?.(); };
    // locale 变化由下方 effect 处理。
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, []);

  // 应用 locale 变化时实时切换语言。
  useEffect(() => {
    if (firstRun.current) { firstRun.current = false; return; } // 初始 locale 已在 init 中传入
    (window as any).RWikiChat?.setLocale?.(locale);
  }, [locale]);

  return null;
}
```

在根布局中放置组件，并传入当前频道和 locale（docs-web 从 URL 路径推导 locale）：

```tsx
<RWikiChatWidget channelId="help_center" locale={locale} />
```

启动 docs-web 前先构建并复制 widget：

```bash
cd frontend && npm run build:widget
cp dist/rwiki-chat.js ../docs-web/public/
```
